# 0단계 — 실제 폰에서 타당성 확인

목표는 기능 완성이 아니라 아래 네 가지 질문에 **실제 폰과 실제 대상 앱**으로 답하는 것이다. 답이 나오기 전에는 1단계 이후를 만들지 않는다.

| # | 질문 | 판정에 쓰는 것 |
|---|---|---|
| Q1 | 대상 앱이 원하는 순간에 `SECURE_WINDOW`를 반환하는가 | 진단 앱 기록의 `변화:` / `★ 정상→보안 전환` 줄 |
| Q2 | 보안 화면이 같은 창인가, 새 창인가 (PLAN 2장 A) | `★` 줄의 "창 ID 같음/바뀜" |
| Q3 | 주입 탭이 대상 앱에 전달되는가 | 테스트벤치 카운터, 실제 앱에서 눈으로 확인 |
| Q4 | 400ms 감시에서 `INTERVAL_TIME_SHORT`가 얼마나 나오는가, 100ms 연타 간격은 실제로 얼마인가 | 진단 기록 요약, 테스트벤치 간격 |

## 준비

1. GitHub 저장소의 Releases → `triggertap-latest`에서 두 APK를 폰으로 받아 설치 (출처를 알 수 없는 앱 허용 필요).
   - `triggertap-probe.apk` — **트리거탭 진단**
   - `triggertap-testbench.apk` — **트리거탭 테스트벤치**
2. 진단 앱을 열고 **접근성 설정 열기** → 설치된 앱(또는 다운로드한 앱) → *트리거탭 진단* 켜기.
   - Android 13+에서는 직접 설치한 앱의 접근성 권한이 "제한된 설정"으로 막힐 수 있다. 그러면 설정 → 애플리케이션 → 트리거탭 진단 → 오른쪽 위 ⋮ → **제한된 설정 허용** 후 다시 켠다.
3. 진단 앱 → **패널 열기**. 화면 위에 어두운 플로팅 패널이 뜬다(제목 줄을 끌어서 옮김).

패널 버튼: `감시 ▶/■` 캡처 감시 켜기·끄기 · `표식` 빨간 원 표시/숨김(끌어서 누를 위치 지정) · `탭1` 한 번 탭 · `탭×N` 설정 횟수만큼 연타 · `■` 모두 중지 · `닫기` 패널 닫기.

> 0단계 앱은 캡처 결과로 **자동 탭을 보내지 않는다.** 탭은 패널 버튼을 누를 때만 나간다. 결제·송금·삭제 등 되돌릴 수 없는 버튼을 시험 위치로 쓰지 않는다.

## 시험 A — 테스트벤치 (기준선)

1. 진단 앱 → 대상 앱 선택 → *트리거탭 테스트벤치*.
2. 테스트벤치 실행 → 패널 `감시 ▶`. 상태 줄에 `#창ID SUCCESS`가 반복되어야 한다.
3. 테스트벤치 **3초 뒤 보안 켜기** → 상태가 `SECURE_WINDOW`로 바뀌는지 본다. (같은 창 전환)
4. 보안 끄기 → **3초 뒤 보안 새 창** → 붉은 화면이 뜨며 `SECURE_WINDOW`가 되는지, 창 ID가 바뀌는지 본다. (새 창 전환)
5. 패널 `감시 ■`. `표식` → 빨간 원을 테스트벤치의 회색 영역 가운데로 끌어 놓고 → `표식`으로 숨김.
6. `탭1` → 테스트벤치 숫자가 1 오르는지. `탭×5` → 5 오르는지, 아래 기록의 간격(ms)이 얼마인지.
7. 테스트벤치 체크박스 **가려짐 필터**, **접근성 민감**을 각각 켜고 6을 반복 → 영역 수신 수가 오르는지 기록.
   (창 수신은 오르는데 영역 수신이 안 오르면 뷰 보안 필터가 주입 탭을 버린 것)
8. 보안 켠 상태에서도 6을 반복 → 보안 화면에 탭이 전달되는지.

## 시험 B — 실제 대상 앱

1. 대상 앱 선택 → 실제 앱. 앱을 열고 `감시 ▶`.
2. 평소처럼 앱을 사용해 보안 화면(캡처가 막히는 화면)으로 들어갔다 나온다. 진단 앱 기록에 `★ 정상→보안 전환`이 찍히는지, 그때 어떤 화면이었는지 메모.
3. **안전한 버튼**(예: 탭해도 아무 일 없는 빈 곳, 새로고침 등)에 표식을 놓고 `탭1` → 앱이 반응하는지 눈으로 확인.
4. 가능하면 보안 화면 위의 안전한 지점에서도 3을 반복.

## 결과 보내기

- 진단 앱 → **보고서 복사**, 테스트벤치 → **기록 복사** 결과를 대화에 붙여넣는다. 화면 내용·이미지는 들어 있지 않다(결과 코드, 창 ID, 좌표, 타이밍, 기기 모델만).
- 시험 B는 앱 이름과 "어느 화면에서 보안 전환이 됐는지 / 탭이 먹혔는지"를 한두 줄로 덧붙인다.

## 판정 기준

| 결과 | 다음 |
|---|---|
| Q1·Q3 모두 예 | 1단계(core 로직) 진행 |
| Q1 아니오 (보안 오류가 안 나오거나 항상 나옴) | 이 방식으로는 트리거를 만들 수 없음 → 명세 재검토 |
| Q3 아니오 (탭 무시) | 대상 앱이 주입 입력을 거부 → 명세 재검토 |
| Q2 "바뀜" | PLAN 2장 A 보완안(창 ID 비고정)을 1단계에 반영 |
| Q4 간격 오류 잦음 | 기본 감시 간격 상향 |

## 알려진 한계 (0단계 앱)

- 기록은 메모리에만 있어 진단 앱 프로세스가 종료되면 사라진다. 시험 직후 복사한다.
- 탭 전 표식을 숨기느라 첫 탭 전에 약 150ms 대기가 있다(실제 제품에서는 표식이 미리 제거되어 있어 이 대기가 없다).
- 테스트벤치의 "주입" 표시는 Android 비공개 플래그를 읽는 참고값이다.
- 세로 방향, 기본 디스플레이만 가정한다.
