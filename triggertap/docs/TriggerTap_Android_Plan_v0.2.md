# 트리거탭 — 캡처 차단 시 같은 위치를 5회 연타하는 Android 앱

작성일: 2026-09-24  
버전: 0.2 — 사용자 추가 요구 반영  
상태: 개발 요구사항·설계 문서. APK나 구현 완료 보고서가 아니다. 실제 대상 앱·단말의 호환성과 타이밍은 미검증이다.

## 1. 이번 버전의 확정 요구

> 사용자가 지정한 앱의 캡처 가능 여부를 감시하다가, 보안상 캡처 거부가 확인되면 사용자가 지정한 한 좌표를 약 0.1초 간격으로 5번 터치한다.

사용자가 제공한 이미지의 배경·아이콘·문구는 인식 대상으로 사용하지 않는다. 빨간 표시는 누를 위치를 설명하는 참고일 뿐이다. 이미지에서 임의로 정한 좌표를 실행값으로 하드코딩하지 않는다. 실제 폰에서 사용자가 터치 지점 하나를 지정한다.

이전 0.1 문서의 ‘2~3개 단계별 좌표를 순서대로 클릭’은 이 버전의 기본 기능이 아니다. 여기서는 **동일 좌표 5회 연타**로 변경한다.

| 항목 | 기본 요구·설정 |
|---|---|
| 클릭 위치 | 사용자 지정 한 지점, 회차 동안 동일 좌표 |
| 클릭 횟수 | 기본 5회, 설정 범위 1~10회 |
| 클릭 간격 | 시작 시점 사이 100ms 목표, 설정 범위 80~200ms |
| 한 번 누르는 시간 | 초기 시험값 30ms |
| 첫 클릭 전 의도적 대기 | 0ms. 유효성 확인·API 처리 시간은 별도 |
| 감시 간격 | 초기 시험값 400ms. 클릭 간격과 별개 |
| 트리거 | 현재 대상 창의 명시적인 보안 캡처 오류 |
| 차단 확인 횟수 | 빠른 설정: 유효한 오류 1회. 선택적 안정 설정: 연속 2회 |
| 기본 실행 방식 | 정상 캡처 확인 후 차단으로 바뀌면 한 회차 |
| 실행 후 | 5회 전달 완료 또는 안전 중단 후 정지 |
| 이미지 처리 | 성공 여부만 사용. 이미지 분석·저장·전송 없음 |
| 초기 환경 | Android 14 이상, 기본 디스플레이, 전체 화면, 세로 방향 |
| 제외 | 색상·문자·아이콘 인식, AI, OCR, 서버, 로그인, 루팅, 보안 해제 |

‘0.1초 전후’는 각 터치의 시작 시점 사이 약 100ms로 해석한다. 5회를 0.1초 안에 모두 끝내거나 0.1초 동안 누르고 다시 0.1초 쉬라는 뜻이 아니다. 무작위 타이밍·무작위 좌표 이동은 넣지 않는다.

## 2. 동작 흐름

```text
사용자가 대상 앱·터치 위치를 등록
    ↓
사용자가 감시 시작
    ↓
대상 앱의 정상 캡처 결과 확인 → 감시 준비
    ↓
대상 창의 캡처 시도를 주기적으로 수행
    ├─ 성공: 자원 해제 후 감시 유지
    ├─ 일반 실패: 클릭하지 않고 오류별 처리
    └─ 명시적 보안 오류: 현재 대상·회차·환경 재확인
                              ↓
                      먼저 회차 실행 잠금
                              ↓
             같은 좌표 5회 / 약 100ms 시작 간격
                              ↓
                   완료 또는 중단 → 정지
```

캡처 차단은 내용 분석으로 알아내지 않는다. 앱이 원래부터 계속 차단되어 있다면 정상→차단 전환 모드는 실행하지 않는다. ‘시작 시 이미 차단되어 있어도 한 회차 실행’은 사용자 확인을 받는 별도 옵션으로 두고 기본은 끈다.

계속 차단되어 있다는 이유로 5회씩 반복 실행해서는 안 된다. 향후 반복 모드를 추가한다면 정상 캡처 복귀를 연속 2회 확인한 뒤 새로운 차단이 발생해야 다시 한 회차를 실행하게 한다. 첫 버전에서는 수동 재시작을 기본으로 한다.

## 3. 캡처 차단 감지의 구현 근거와 한계

`AccessibilityService.takeScreenshotOfWindow()`와 `ERROR_TAKE_SCREENSHOT_SECURE_WINDOW`는 API 34에 추가됐다. 이 창 단위 API를 기본 감지기로 사용한다. 보안 오류 외에 간격·권한·창 식별 오류도 있으므로 ‘실패했으면 무조건 클릭’으로 구현하지 않는다. [S1]

AOSP 공식 테스트에는 보안 창의 창 캡처가 위 오류를 반환하는 사례가 있다. 반면 디스플레이 전체 캡처는 성공하되 보안 창 내용이 포함되지 않는 사례도 있다. 따라서 수동 스크린샷 실패, 검은 화면, 전체 화면 캡처 성공을 창 캡처의 보안 오류와 동일하게 취급하지 않는다. [S2]

해당 앱에서 원하는 순간에 실제로 보안 오류가 나오는지, 접근성으로 대상 창을 신뢰할 수 있게 식별할 수 있는지, 그 화면에 터치가 전달되는지는 각각 검증해야 한다. 항상 캡처를 막는 앱에서는 이 신호만으로 버튼 활성화나 내용 변화 시점을 구분할 수 없다.

### 감시 간격과 클릭 간격을 분리한다

확인한 AOSP 소스에는 캡처 요청 간격 상수 333ms가 있고, 창 캡처 서버 구현은 같은 창에 대한 지나치게 빠른 요청을 간격 오류로 거부한다. 이 값은 공개 API의 영구 보장값이 아니라 확인한 소스 구현의 값이다. 앱 코드에서 비공개 상수를 호출하거나 모든 제조사에 동일하다고 가정하지 않는다. [S3][S4]

초기 감시 간격을 400ms로 두고 오류 발생 시 500→750→1,000ms로 늘리는 방안을 시험한다. 항상 동시 요청은 하나만 유지한다. 정기 감시와 창 변경 이벤트가 같은 요청 제한기를 사용하도록 해 이벤트 폭주로 캡처를 남발하지 않는다.

400ms 감시에서 차단이 충분히 지속되고 요청이 지연되지 않는다는 가정이면 다음 확인까지 0~400ms에 캡처·콜백 처리 시간이 더해진다. 이는 계획값에서 계산한 범위이지 측정치나 최악 시간 보장이 아니다. 짧게 나타났다 사라지는 차단은 놓칠 수 있다. **차단 발생부터 첫 터치까지 100ms 이내라고 보장하지 않는다.**

빠른 설정에서는 명시적 보안 오류 1회로 시작한다. 안정 설정의 2회 확인은 오작동 후보를 줄일 수 있지만 감지 지연과 짧은 신호 누락 가능성이 커진다. 실제 단말 진단 후 선택한다.

## 4. 100ms × 5회 터치 엔진

목표 시간표는 첫 터치 시작을 0ms로 할 때 다음과 같다.

| 회차 내 터치 | 목표 시작 | 초기 누름 시간 | 목표 종료 |
|---|---:|---:|---:|
| 1 | 0ms | 30ms | 30ms |
| 2 | 100ms | 30ms | 130ms |
| 3 | 200ms | 30ms | 230ms |
| 4 | 300ms | 30ms | 330ms |
| 5 | 400ms | 30ms | 430ms |

약 0.43초의 계획된 연타이며 실제 실행 시간은 달라질 수 있다. 캡처 차단을 알아내는 시간은 이 표에 포함하지 않는다.

터치는 접근성 `dispatchGesture()`를 통해 보낸다. `StrokeDescription`에는 밀리초 단위 시작 시각·지속 시간을 설정할 수 있으며, 이동 없는 경로로 한 번의 탭을 구성할 수 있다. [S1][S5]

### 선택한 구현 전략: 한 번씩 전송

5개 터치를 한꺼번에 예약하지 않고, 단일 탭을 전송한 뒤 완료 콜백을 확인하고 다음 탭을 전송한다. 이렇게 해야 중지·대상 이탈·취소에 대응해 아직 보내지 않은 터치를 멈추기 쉽다. 완료·취소 콜백은 Android가 제공한다. [S6]

후속 탭의 목표 시작은 직전 실제 전송 시작 + 100ms로 계산한다. 콜백을 받은 뒤 무조건 100ms를 추가로 쉬는 방식으로 구현하지 않는다. 콜백이 늦으면 다음 탭도 늦출 수 있지만 밀린 탭을 몰아서 보충하거나 겹쳐 보내지는 않는다.

```text
검증된 보안 오류 수신
→ 실행 상태를 RUNNING으로 먼저 전환
→ 화면·대상 창·세션 유효성 확인
→ 탭 1회 전송, 실제 전송 시각 기록
→ 완료 콜백 대기
→ 취소/전송 거부/시간 초과: 남은 탭 중단
→ 완료: 직전 전송 + 100ms까지 남은 시간 대기
→ 아직 남은 횟수가 있으면 다시 유효성 확인 후 다음 탭
→ 설정 횟수 완료: DONE
```

`dispatchGesture()`는 진행 중인 다른 제스처를 취소할 수 있으므로 사용자 터치나 다른 자동화 서비스와 병행하지 않도록 안내한다. 이벤트가 확대 기능 등으로 영향을 받을 수 있다는 점도 진단한다. [S1]

제스처 완료는 대상 앱이 업무를 1회 처리했다는 뜻이 아니다. 빠른 연타가 중복 클릭 방지나 더블 탭 처리와 충돌하는지는 실제 앱에서 시험한다. 완료 화면은 ‘터치 전달 5/5’라고 표시하고 ‘접수 성공’ 등 확인되지 않은 업무 결과는 표시하지 않는다.

## 5. 터치 위치 설정

사용자는 대상 앱을 열고 위치 편집 모드를 켠 뒤 화면 위의 표식 하나를 끌어서 누를 지점을 지정한다. 앱이 사진 속 빨간 원을 실시간으로 찾거나 원 안 여러 곳을 무작위로 누르는 방식이 아니다.

접근성 오버레이를 위치 편집 UI로 사용하되, 실제 앱·단말에서 표시 및 터치 간섭 여부를 검증한다. 접근성 서비스는 오버레이를 표시할 수 있다. [S1]

편집 중에는 자동 실행을 끈다. 표식 위치는 저장하고 실제 감시·실행 전 표식은 제거한다. 중지용 제어는 터치 지점과 겹치지 않는 곳에 둔다. 표식이 제거되지 않거나 안전한 중지 수단을 사용할 수 없으면 실행하지 않는다.

저장할 정보는 실제 디스플레이 좌표, 기준 화면 크기, 회전, 대상 창 경계, 디스플레이 배율과 대상 앱 식별 정보다. 정규화 좌표는 참고값으로 저장할 수 있지만 화면 크기 변경 시 비율만 곱해 임의로 계속 실행하지 않는다. 제공된 참고 이미지의 크기와 실제 단말의 좌표계가 같다고 가정하지 않는다.

빠른 연타 중에는 최초 확정한 동일 좌표를 사용한다. 대상 창이 교체되거나 화면 방향·크기가 바뀌면 기본적으로 남은 탭을 중단한다. 같은 창의 내부 UI 변화는 이미지 분석을 하지 않으므로 감지하지 못할 수 있다. 결과 화면을 읽고 다음 버튼을 찾아 누르는 다단계 자동화는 이번 요구가 아니다.

## 6. 최소 UI

메인 화면에 아래 설정과 조작만 둔다.

| 화면 요소 | 내용 |
|---|---|
| 대상 앱 | 사용자가 선택, 임의 추정 금지 |
| 위치 지정 | 화면 위 표식 하나로 좌표 등록 |
| 클릭 수 | 기본 5회 |
| 클릭 간격 | 기본 0.10초 |
| 진단 | 클릭 없이 캡처 성공·보안 거부·일반 오류 표시 |
| 시작/중지 | 실행 상태를 명확히 표시 |
| 결과 | 터치 전달 횟수, 중단 이유, 감지·전송 타이밍 |

감시 간격, 빠른/안정 확인, 이미 차단된 상태에서 시작 옵션은 고급 설정에 둔다. 첫 실행은 진단 모드로 시작하고, 호환성 및 위치 시험을 거친 뒤 사용자가 실제 자동 실행을 켜도록 한다.

## 7. 오류·중복·중지 처리

| 조건 | 동작 |
|---|---|
| 유효한 대상 창의 보안 오류 | 설정 확인 횟수 충족 시 한 회차 시작 |
| 캡처 간격 오류 | 클릭 0회, 감시 간격 확대 |
| 권한·내부 오류·응답 시간 초과 | 클릭 0회, 원인 표시 후 중단 |
| 잘못된 창 | 클릭 0회, 최신 대상 창을 다시 확인 |
| 캡처 성공이지만 검거나 빈 이미지 | 실패로 추정하지 않음 |
| 보안 오류 반복/중복 콜백 | 이미 RUNNING/DONE이면 추가 회차 시작 금지 |
| 탭 전송 거부·취소·시간 초과 | 해당 탭 자동 재시도 금지, 남은 탭 중단 |
| 중지·대상 이탈·잠금·등록 조건 변경 | 아직 전송하지 않은 탭 취소 |
| 프로세스 또는 서비스 재시작 | 자동 감시·자동 터치 재개 금지 |

감시·실행 상태는 하나의 직렬 처리 경로에서 관리하고 `sessionId`, `requestId`, `runId`로 오래된 콜백을 구분한다. 중지·재시작 시 이전 세션을 무효화한다. 캡처 오류를 받은 뒤 터치하기 전에도 같은 앱·창이 앞에 있는지 재검증한다. 화면 확인과 입력 사이의 경쟁 상태를 완전히 없앴다고 주장하지 않는다.

한 회차가 시작되면 캡처 요청은 멈추고 5회 터치에 집중한다. 다음 터치를 보낼 때마다 중지 상태를 다시 확인한다. 기본 5회지만 안전 중단 시 0~4회만 전달될 수 있다. 이미 전달된 터치와 이미 발생한 대상 앱 동작은 되돌릴 수 없다.

## 8. 기술 구성·데이터 처리

Kotlin 네이티브 앱과 AccessibilityService를 중심으로 구현한다. 설정 UI에는 Compose를 제안한다. 실제 구현 시 안정 SDK·라이브러리 버전을 확인하고 고정하며, 특정 최신 버전을 이 문서에서 추정해 지정하지 않는다.

```text
UI/설정
  ├─ 대상 앱·창 확인
  ├─ 캡처 요청 제한기와 오류 분류
  ├─ 트리거 상태 관리
  ├─ 100ms 목표 순차 탭 실행기
  ├─ 위치 편집 오버레이
  └─ 로컬 진단 기록
```

사용자가 접근성 서비스를 직접 활성화해야 하며 서비스 메타데이터에 캡처·제스처·창 조회 기능을 선언한다. 사용자 설명과 동의를 포함하고 일반 자동화 도구를 장애인 전용 접근성 도구로 허위 표시하지 않는다. [S1]

앱은 정상 캡처 결과를 받더라도 분석하거나 파일로 저장하지 않는다. 반환된 HardwareBuffer는 오래된 세션의 결과를 포함해 사용 종료 시 닫도록 한다. 이 자원 해제 요구는 공식 문서에 명시되어 있다. [S7]

인터넷·갤러리·마이크·카메라 권한, 서버, 광고·분석 SDK는 초기 범위에서 제외한다. 로그는 화면 내용 없이 오류 코드, 회차 ID, 타이밍, 터치 전달 개수만 제한적으로 남긴다. 사용자가 로그 삭제를 할 수 있게 한다.

## 9. 설정 데이터 예시

실제 앱과 좌표는 미정이므로 null로 둔다. 아래 예시는 실행 가능한 등록값이 아니며 필수 값이 비어 있으면 시작을 차단한다.

```json
{
  "schemaVersion": 2,
  "targetPackage": null,
  "point": null,
  "calibration": null,
  "triggerMode": "NORMAL_TO_SECURE",
  "pollIntervalMs": 400,
  "baselineSuccessCount": 1,
  "secureFailureCount": 1,
  "firstTapDelayMs": 0,
  "tapCount": 5,
  "tapStartIntervalMs": 100,
  "tapHoldMs": 30,
  "executionMode": "ONE_SHOT",
  "dryRun": true,
  "calibrationVerified": false
}
```

`point`에는 실제 화면 좌표를, `calibration`에는 해당 좌표가 등록된 화면 환경을 저장한다. 실행 전 좌표 범위, 양수 타이밍, 누름 시간이 클릭 간격보다 짧은지, 횟수 상한과 검증 완료 여부를 검사한다.

## 10. 개발·인수 테스트

먼저 보안 설정을 전환할 수 있는 개발용 테스트 화면과 터치 횟수 카운터를 만든다. 실제 대상 앱 진단은 클릭 없이 시작한다.

| 시험 | 통과 조건 |
|---|---|
| 정상→보안 차단 지속 | 기본 설정에서 같은 좌표의 탭이 정상 경로에서 5회 전달됨 |
| 차단 유지 | 최초 회차 이후 추가 탭 0회 |
| 일반 캡처 오류 | 해당 오류로 시작되는 탭 0회 |
| 진단 모드 | 모든 경우 자동 탭 0회 |
| 시작부터 차단, 기본 모드 | 정상 기준 확인 전에는 탭 0회 |
| 빠른 설정에서 보안 오류 1회 | 유효성 확인 후 한 회차 시작 |
| 중복·늦은 콜백 | 6번째 탭이나 추가 회차가 발생하지 않음 |
| 두 번째 탭 후 중지 | 아직 보내지 않은 후속 탭 중단 |
| 앱·창 전환, 잠금, 회전 | 후속 탭 중단 |
| 취소·전송 거부 | 자동 재시도나 몰아서 보충하는 탭 없음 |
| 데이터 점검 | 캡처 이미지 파일, 화면 원문 로그, 네트워크 전송 없음 |

기본 타이밍 시험은 개발용 화면에서 실제 수신된 터치 시작 간격과 개수를 측정한다. 앱 내부 ‘전송 시각’과 대상 화면 ‘입력 수신 시각’을 구분한다. 100ms는 목표이며 시험 전부터 허용 오차나 성공률을 보장하지 않는다. 평균·범위·누락·취소와 부하 상황별 결과를 기록한 뒤 사용 단말에 맞게 간격과 누름 시간을 조정한다.

실제 대상 앱에서는 캡처 오류 감지와 터치 수신을 각각 확인한다. 비가역적인 결제·송금·삭제 등을 시험 동작으로 사용하지 않는다. 앱이 자체적으로 빠른 중복 입력을 무시한다면 터치 전달 5회와 실제 처리 5회가 다를 수 있음을 결과에 명시한다.

## 11. 개발 전달용 핵심 지시문

> Android 14 이상용 Kotlin 앱을 만든다. 사용자가 선택한 전면 앱의 창에 takeScreenshotOfWindow를 호출하고 명시적인 보안 창 오류만 트리거로 사용한다. 실제 폰에서 지정한 좌표 하나를 기본 100ms 시작 간격, 30ms 누름, 5회로 터치한다. 화면 이미지·색·글자·아이콘은 분석하지 않는다. 감시 간격은 초기 400ms로 두되 OS의 요청 간격 오류에 대응해 늘리고, 100ms 터치 간격과 혼동하지 않는다. 빠른 설정은 유효한 보안 오류 1회로 시작한다. 한 탭씩 전송하고 완료·취소를 확인하며 남은 시간을 계산해 다음 탭을 예약한다. 동시에 여러 제스처를 보내거나 밀린 탭을 몰아서 보내지 않는다. 실행 잠금과 세션 ID로 중복·오래된 콜백을 막는다. 기본은 5회 완료 후 정지이며 차단 유지 중 재실행하지 않는다. 사용자 중지, 앱·창 이탈, 잠금, 환경 변경, 입력 실패 시 후속 탭을 중단한다. 클릭 없는 진단과 위치 설정, 테스트용 보안 전환 화면 및 실제 입력 카운터를 포함한다. APK 및 소스의 완성·기기 호환성·타이밍은 실제 빌드와 시험 후에만 확인됐다고 표시한다.
