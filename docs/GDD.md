## 1. 핵심 판타지 & 코어 루프

**핵심 판타지**: "나는 신생 구단의 감독 겸 스카우터다. 재능은 있지만 다듬어지지 않은 신인을 스카우트하고, 직접 훈련 스케줄을 짜서 세계 최고의 선수로 키운 뒤, 내가 설계한 로테이션과 전술로 리그 우승을 노린다."

**코어 루프 (한 사이클)**

```
스카우트(가챠)
   → 육성 시즌 진입 (신인 카드 1명, 턴제 육성)
   → 육성 종료("졸업") → 로스터 정식 편입, 능력치 확정
   → 팀 편성 (라인업 / 로테이션 / 전술)
   → 리그·대회 경기 시뮬레이션
   → 보상 획득 (재화, 강화 소재, 신규 선수 조각 등)
   → 재화로 재스카우트 / 기존 선수 강화 → 루프 반복
```

이중 루프 구조로 설계한다:
- **단기 루프(세션당 5~15분)**: 육성 턴 진행, 연습경기, 일일 미션
- **중기 루프(1~2주)**: 한 선수의 육성 시즌 완주, 리그 한 시즌 진행
- **장기 루프(시즌/이벤트 단위)**: 팀 완성도 상승, 랭킹 등반, 신규 캐릭터 픽업 이벤트

**루프를 닫는 것은 선수의 수명이다(v0.3).** 위 사이클은 "로스터가 완성되면 끝"이 되기 쉽다 —
실제로 프로토타입에서 시즌 5 이후 우승률이 90%를 넘겨 게임이 끝나 버렸다. 그래서 선수에게 **전성기와 은퇴**를 주었다:
주전은 전성기를 지나면 기량이 떨어지고 결국 은퇴한다(코치로 남는다). 감독이 매 시즌 해야 할 일이
**"더 강해지기"에서 "세대를 이어 가기"로** 바뀌고, 스카우트·육성 루프가 리그가 끝날 때까지 계속 돌아간다.
규칙과 검증 수치는 `docs/league-and-economy.md` A.3.6 · A.4.4.

## 2. 캐릭터(선수 카드) 시스템

### 2.1 포지션 (배구 고유 룰 반영)

| 포지션 | 약자 | 역할 |
|---|---|---|
| 세터 | S | 토스 배급, 팀 공격 설계의 핵심. 팀 전체 공격 성공률에 배수 영향 |
| 아웃사이드 히터(윙스파이커) | OH | 주공격수, 리시브도 겸함 |
| 아포짓 스파이커 | OP | 후위 공격 전담, 리시브 부담 적고 순수 화력형 |
| 미들블로커 | MB | 속공 + 블로킹의 핵심, 높이 스탯 중요 |
| 리베로 | L | 수비 전담, 후위 한정 출전, 서브 불가 등 실제 룰 반영 |

### 2.2 희귀도 & 성장

- 등급: N → R → SR → SSR (+ 한정/픽업 등급)
- 스탯: 서브, 리시브, 토스(세트), 스파이크, 블로킹, 디그, 스피드, 파워, 스태미나, 멘탈(클러치)
- 잠재력(Potential) 상한 + 한계돌파(중복 카드로 상한 해제) 구조
- **나이 · 전성기 · 은퇴**: 선수는 시즌마다 한 살 먹는다. 전성기(아포짓·미들 ~25세 / 아웃사이드 ~26 / 세터·리베로 ~27)를 지나면
  실효 능력치가 떨어지고, 31~33세에 은퇴해 **코치(서포터)로 남는다**. 카드를 고를 때 OVR 만이 아니라
  **"몇 시즌 쓸 수 있는가"** 를 함께 보게 만드는 축이다. 한계돌파는 출발점을 올릴 뿐 하락을 늦추지는 않는다.
  상세: `docs/league-and-economy.md` A.3.6
- 개인 특기 스킬(패시브/트리거형): 예) "타임서브 성공 시 다음 랠리 리시브 확률 +", "2단 연속 실점 시 정신력 발동으로 공격력 회복" 등 배구 특유의 리듬을 스킬화

### 2.3 성장 서사 (인연/스토리)

- 선수별 개인 스토리 이벤트(육성 중 발생)
- 팀 동료 간 "인연 보너스"(듀오/트리오 시너지) — 특정 선수 조합 로스터 편성 시 스탯 보너스

> **구현 상태(2026-09).** 성격 태그 3개를 6가지 **아키타입**(승부사·냉정파·분위기 메이커·노력파·수줍음·스타 기질,
> `web/engine/commentary.js`)으로 묶어 표현 계층 전체가 쓴다 — 캠프 **카드 스토리 3컷**이 아키타입별로 갈리고(효과는 동일),
> **인연 순간**(T7, 동문·라이벌 서포터, 서사만·효과 0), 경기 **해설·컷인의 성격 양념**(클러치 강타·에이스·블로킹·클러치 범실),
> 경기 전 **서사 줄**(친정 대결·숙적·선두 다툼·이번 시즌 전적, [world.md](world.md) 3절). 전부 판정 밖이라 캘리브레이션이 그대로다.
> 인연 **보너스**(스탯)는 미구현 — 붙일 때 하네스로 정한다([training-mode.md](training-mode.md) 6.4).

## 3. 육성 모드 (메인 콘텐츠)

우마무스메형 "턴제 육성"을 배구에 맞게 각색.

- **시즌 구조**: 예) 총 N턴(주 단위) 육성 시즌. 매 턴 선택지:
  - 개별 훈련(서브/리시브/토스/스파이크/블로킹 중 선택, 스탯 상승 + 피로도 누적)
  - 휴식(피로도 회복, 컨디션 관리)
  - 특훈 이벤트(랜덤/조건부 발생, 큰 상승폭 + 리스크)
  - 연습경기(중간 점검, 팀워크 스탯 상승)
- **컨디션 · 피로도 · 부상 리스크**: 무리한 훈련 스택 시 부상 확률 상승 → 이후 시즌 결장/스탯 페널티
- **평가전**: 육성 중간중간 배치되는 미니 매치로 성장 체감 제공 (모의고사 개념의 배구 버전)
- **졸업**: 육성 시즌 종료 시 스탯 확정, 팀 로스터에 정식 편입되어 이후 리그 모드의 영구 자산이 됨
- **서포터(B안 확정)**: 졸업한 로스터 선수를 육성 시작 시 서포터로 편성해 훈련 보정·인연 보너스를 받음. 별도 서포트 가챠는 두지 않음 — "좋은 로스터 → 좋은 육성 → 더 좋은 로스터"의 플라이휠. 상세는 [training-mode.md](training-mode.md)

## 4. 팀 매니지먼트 (감독 파트)

- **로스터**: 출전 6인 + 리베로 + 벤치(교체 자원)
- **라인업/로테이션**: 배구 고유 규칙 반영 — 시계방향 로테이션, 서브 순서, 리베로 전담 교체 규칙, 세트당 교체 횟수 제한 등을 시스템으로 구현해 "배구다움"을 매니지먼트 재미로 승화
- **전술 슬라이더**: 공격 전개 비중(속공/시간차/이동공격/후위공격), 리시브 포메이션, 서브 전략(강서브 vs 안정서브)
- **팀 케미스트리**: 세터-공격수 호흡도(함께 뛴 경기 수로 누적), 인연 보너스 반영

## 5. 경기 시뮬레이션

- **표현 방식**: 실시간 3D 렌더링 대신, 2D 심플 연출(코트 위 아이콘 애니메이션) + 랠리 단위 텍스트/로그 중계. 연출 비용을 통제하면서도 몰입감 확보 (모바일 매니저 게임의 표준 해법)
- **세트 규칙**: 5세트 3선승, 랠리포인트제, 25점(5세트 15점), 2점차 승리 등 실제 배구 규칙 반영
- **랠리 판정 체인(개념)**: 서브 → 리시브 → 토스 → 공격(스파이크/속공) → 블로킹/디그 순으로 단계별 스탯 대결 + 확률 + 스킬 발동을 계산해 득실점 결정. 각 단계 결과가 다음 단계 성공률에 영향을 주는 연쇄 구조로, 배구 특유의 "랠리 흐름"을 재현
- **변수**: 컨디션, 클러치(접전 상황 멘탈 스탯), 팀워크, 관중/원정 보정 등

## 6. 시즌 / 리그 구조

- **난이도 곡선**: 시즌 1 중위권 → 시즌 2~3 첫 우승 → **시즌 4 이후 고원**(우승률 55~65%). AI 6구단은 성장률 상한(잠재력의 80%)에서 멈추고,
  플레이어는 로스터의 노화에서 멈춘다. AI 구단도 노쇠한 선수를 신인으로 세대교체하며 리그 수준을 유지한다 — `docs/league-and-economy.md` A.3.6 · A.4.4
- 정규 시즌(자동 진행 지원 + 수동 관전 선택 가능), 순위표, 승강 여부는 추후 결정
- 컵대회·챔피언십 등 별도 대회
- **PvP**: 비동기 대전(상대 유저 팀 스냅샷과 서버 시뮬레이션으로 대결) — 실시간 대전은 1차 범위에서 제외
- 시즌제 랭킹 및 시즌 보상

## 9. 비주얼 전략 (아트 · 카드 · 연출)

> 수집형 가챠에서 카드 일러스트는 상품 그 자체다. 게임플레이가 리텐션을, 비주얼이 획득과 매출을 담당한다. 따라서 아트는 "장식"이 아니라 별도의 제품 라인으로 관리한다.

### 9.1 아트 디렉션

- **스타일**: 일본 애니메풍(가챠 수집형의 주류 문법). 밝은 청춘 스포츠물 톤, 건강한 운동선수 체형.
- **스타일 가이드(필수 산출물)**: 선 두께, 채색 방식(셀/소프트), 신체 비율(7~7.5등신), 눈 디자인 규격, 광원 방향, 색 팔레트. AI 생성 시 프롬프트 템플릿·네거티브·모델/시드 고정값까지 가이드에 포함한다.
- **캐릭터 구분 원칙**: 실루엣(헤어 형태·키), 헤어/눈 컬러, 유니폼 번호·구단 컬러의 3중 구분. 포지션별 체형 경향(MB 장신, L 단신·민첩)으로 포지션이 그림에서 읽히게 한다.
- **오리지널 원칙**: 실제 인물·특정 작품(하이큐 등)·특정 작가 화풍 모사 금지. 프롬프트에 작가명 사용 금지.
- **노출 수위**: **15세 이용가** — 12세 판의 금지선이 경기 장면의 박진감까지 잘라 내는 것이 히어로 시험에서 드러나 v0.2 에서 상향했다. 나체·속옷·과도한 노출·성행위는 계속 금지. **살려야 할 것**(높이·힘·긴장·속도)은 [art-style-guide.md](art-style-guide.md) 1.4.1 에 요구 사항으로 명시했다. 19세까지 열지 않은 이유는 1.4.3.

### 9.2 카드 구성 레이어

| 레이어 | 내용 | 제작 방식 |
|---|---|---|
| L0 배경 | 등급별 색상/패턴, SSR은 애니메이션 배경 | 벡터/셰이더 (엔진) |
| L1 캐릭터 일러스트 | 카드용 크롭 (3:4) | AI 생성 + 리터치 |
| L2 유니폼 로고·번호·구단 엠블럼 | 구단 아이덴티티 | **벡터 수작업 후 합성** |
| L3 프레임 | 등급별 4종 (N/R/SR/SSR) | 벡터, 엔진 런타임 합성 |
| L4 정보 오버레이 | 이름, 포지션 아이콘, 레벨, 한계돌파 별 | UI (엔진) |
| L5 이펙트 | SSR 파티클, 홀로 시머 | 파티클/셰이더 (엔진) |

핵심 트릭: 유니폼 로고·번호·엠블럼은 AI에 맡기지 않고 벡터로 만들어 합성한다. AI 특유의 글자 깨짐을 피하고, 구단 아이덴티티 일관성을 확보하며, 유니폼 교체(코스튬)도 레이어 교체만으로 가능해진다.

### 9.3 캐릭터당 필요 에셋

| 에셋 | 용도 | 규격(안) | 비고 |
|---|---|---|---|
| 카드 풀 일러스트 | 가챠 / 카드 상세 | 3:4, 원본 2048×2732 | 포지션 대표 동작 포즈(스파이크/서브/토스/디그/블로킹) |
| 카드 썸네일 | 리스트 / 편성 화면 | 얼굴 크롭 512² | 풀 일러스트에서 크롭 자동화 |
| 스탠딩(입식) | 육성 모드 대화·이벤트 | 전신 | 표정 차분 4종(기본/기쁨/피로/좌절), 얼굴 파츠 교체로 처리 |
| 코트 SD 토큰 | 경기 연출 | 256² | 포지션 공통 베이스 + 헤어 파츠·번호로 식별 |
| 각성 일러스트 | SSR 각성 2단계 | 3:4 | SSR 한정. 유니폼 변화·연출 포즈 |

### 9.4 등급별 카드 연출 스펙

| 등급 | 프레임 | 배경 | 획득 연출 | 부가 |
|---|---|---|---|---|
| N | 회색 단색 | 단색 | 즉시 공개 | — |
| R | 파랑 | 그라데이션 | 카드 뒤집기 | — |
| SR | 보라/은 | 패턴 + 광택 | 조명 점등 후 뒤집기 | 홀로 시머 |
| SSR | 금 + 파티클 | 애니메이션 배경 | 사전 티징 → 슬로우 리빌 | 각성 시 프레임 진화, 리스트에서 상시 시머 |

가챠 연출 컨셉: **"서브 → 코트 조명 → 카드 리빌"**. 서브 공의 궤적 색으로 등급을 예고(파랑/보라/금/무지개). 10연 시 요약 화면 + 스킵 지원.

### 9.5 AI 생성 + 리터치 파이프라인 (1인 개발 기준)

1. **캐릭터 설정 시트**(텍스트): 이름·구단·포지션·헤어/눈/체형·성격 키워드
2. **레퍼런스 생성**: 3면도 + 표정 시트 생성 → 채택
3. **일관성 고정**: SSR·히어로급은 캐릭터별 LoRA 학습 또는 레퍼런스 조건부 생성. 하위 등급은 프롬프트 + 시드 고정
4. **본 일러스트 생성**: 포즈 제어(ControlNet 등)로 배구 동작 강제. 배경은 단순 코트/조명
5. **리터치(필수)**: 손가락·배구공·팔 관절 등 AI 취약부 수정, 눈/헤어 일관성, 유니폼 로고·번호 벡터 합성, 색보정
6. **업스케일 → 크롭 자동화(카드/썸네일) → Unity 임포트**(스프라이트 아틀라스)

- 도구: 로컬 SD 계열(애니메 특화 체크포인트) + ControlNet + LoRA 학습 환경, 또는 상용 서비스. **사용 모델·서비스의 상용 이용 라이선스 확인 필수**(일부 애니메 모델은 상업 이용 제한).
- 리터치 QA 체크리스트: 손가락 수 / 배구공 패널 구조 / 유니폼 좌우 대칭 / 눈 크기·색 일관성 / 포지션-동작 적합성 / 등급 대비 화려함 편차

### 9.6 런칭 아트 물량 산정

- 런칭 카드풀: 6개 가상 구단 × 7명(S1·OH2·OP1·MB2·L1) = **42명**
- 등급 분포(안): SSR 10 / SR 14 / R 18. N은 제네릭 "무명 신인" 카드 수 종으로 육성 재료 역할
- 에셋 수: 42 × (카드 1 + 스탠딩 1 + SD 토큰 1) = 126 + SSR 각성 10 = **약 136장** + 공용 에셋(프레임 4, 구단 엠블럼·유니폼 6세트, 코트 배경 3, 가챠 연출, UI 아이콘)
- 공수 추정: AI + 리터치 기준 캐릭터당 4~8시간 → 42명 ≈ 170~340시간 ≈ 1인 풀타임 **1.5~2.5개월**(개발 병행 시 더 길어짐)
- 런칭 후: 월 2~4명 신규(픽업) 공급 목표

### 9.7 프로토타입 원칙

비주얼이 핵심 상품이라도 아트를 먼저 만들지 않는다. Phase 1은 실루엣 + 컬러 블록 플레이스홀더로 루프를 검증하고, **병렬로 히어로 3~5명만 정식 퀄리티로 제작**해 "이 그림에 돈을 쓸까"를 별도로 테스트한다.

| 리스크 | 대응 |

## 11. 기술 스택 (확정: Unity 2D)

**결정: Unity 2D.** 1인 개발 + 비주얼 중심 가챠라는 조건에서 카드 연출 자유도·에셋 생태계·레퍼런스가 가장 풍부하다. (검토했던 대안: Flutter — UI 개발은 빠르나 연출 한계, React Native — 게임 특화 렌더링 취약.)

- **렌더링**: 2D URP. 카드 일러스트는 스프라이트 아틀라스로 관리하고, 고해상도 원본은 Addressables로 지연/원격 로드해 앱 용량을 통제
- **UI**: UGUI(에셋 호환성 우선) 또는 UI Toolkit — 프로토타입 단계에서 하나로 고정
- **연출**: 파티클 시스템 + 트윈 라이브러리(DOTween류), 리빌/각성용 홀로 시머 셰이더. Spine/Live2D는 후순위 옵션(SSR 스탠딩 한정 검토)
- **시뮬레이션 코어**: 엔진 비의존 순수 C# 라이브러리로 분리 → 서버(.NET)와 동일 코드로 판정, 클라이언트는 결과를 리플레이
- **백엔드**: 부정 방지(PvP 랭킹)와 밸런스 패치 유연성을 위해 **서버 권위(server-authoritative) 시뮬레이션**·인벤토리·가챠 확률 처리. 구체 서비스(자체 .NET 서버 vs BaaS)는 Phase 3에 결정
- **1인 개발 원칙**: 에셋스토어 적극 활용(가챠 연출·UI 프레임워크). 직접 만드는 범위는 시뮬레이션·육성 로직·데이터 파이프라인으로 한정

## 12. MVP 로드맵

- **Phase 0 — 기획 확정** ✅: 스탯 공식, 포지션별 역할 밸런스, 아트 스타일 가이드 확정
- **Phase 1 — 코어 프로토타입** ✅: 선수 1명 육성 루프 + 단일 경기 시뮬레이터 (아트 없이 로직 검증)
- **Phase 2 — 매니지먼트 계층** ✅: 로스터/라인업/로테이션 + 리그 시즌 진행
- **Phase 3 — 경제/서버** ◐: 가챠·재화·천장·한계돌파는 동작. **서버 연동·비동기 PvP 미착수**
- **Phase 4 — 라이브옵스** ☐: 이벤트, 신규 캐릭터 파이프라인, 폴리싱, 스토어 출시 준비
- **아트 트랙(병렬)** ✅: **런칭 42명 카드·전신 + 신인 외형 풀 72종**이 들어와 있고([art-pipeline.md](art-pipeline.md) 12~15절), 화면에서도 쓴다 — 스카우트 실물 카드 뒤집기, 도감, 경기 인트로·컷인·코트 얼굴, 감독실 전신 헤더, 연습생·결원 대체 선수의 얼굴(16절). 엠블럼만 SVG 다. 남은 것은 신인 전신과 육성·결산·은퇴 화면의 활용(16.4). Phase 3부터 월간 신규 캐릭터는 `debutSeason` 훅([rookies.md](rookies.md) 7절)으로 들어간다

**현재 위치**: Phase 1~2 를 **웹(`web/`)에서** 통과했다. 브라우저에서 스카우트 → 12턴 육성 → 졸업 → 라인업 →
리그 시즌(14매치데이 + 포스트시즌)이 한 바퀴 돌고, 경기는 쿼터뷰 코트에서 물리로 재생된다.
로드맵이 상정한 Unity 구현은 아직 `sim/`(경기·육성만, 아카이브) 단계다 — [sim/README.md](../sim/README.md).
**다음 병목은 아트다** — 이미지 생성 도구를 골라 히어로 3명을 끝까지 만들고 휴대폰에서 확인하는 것.
