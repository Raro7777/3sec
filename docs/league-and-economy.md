## 수치의 출처와 권위 (v0.2 에서 바뀐 것)

v0.1 의 수치는 전부 `tools/economy-sim/economy_sim.py`(승률 **로지스틱 근사**)에서 나왔다. 그 뒤 리그·경제 계층이
`web/engine/season.js` 에 **실제 `MatchSimulator` 위로** 구현되면서, 근사 위에서 잡은 초기값이 실제 엔진에서는
맞지 않는다는 것이 드러났다. v0.2 는 본문 수치를 실제 엔진 실측값으로 갈아 끼운 것이다.

| 층 | 스크립트 | 성격 | 이 문서에서의 지위 |
|---|---|---|---|
| **실제 엔진** | `node web/season-check.mjs` (n=200 · 3시즌 · seed 1 · 약 25초) | 진짜 `MatchSimulator` + 진짜 `TrainingSession` | **권위 있는 값.** A.3.1 · A.4 · B.3 의 수치는 전부 여기서 나온다 |
| 근사 모델 | `python3 tools/economy-sim/economy_sim.py` (n=500 · 6 시나리오 · 약 11초) | 승률 = `sigmoid(0.235 × ΔOVR)` · 졸업 OVR 회귀 모델 | **보조.** 천장 확률처럼 대량 표본이 필요한 계산과, 엔진에 없는 대조군(현행 프로토타입 규칙·정식 미션) 전용 |

두 값이 어긋나면 **엔진이 맞다.** 근사 모델이 남긴 차이는 B.3.1 아래 "근사 모델과의 차이"에 수치로 적어 두었다.

> **측정 기준 리비전: `eca38ad`.** 이 문서의 모든 엔진 수치는 그 커밋의 `web/` 를 그대로 돌려 얻었고, 재실행하면 재현된다.
>
> **⚠ 작성 시점에 `web/engine/` 에 커밋되지 않은 선수 고유 스킬 시스템(`skills.js`)이 작업 중이었다.** 그 변경이 들어간 작업본에서는
> 졸업 인스턴스의 스킬 레벨이 경기 판정에 반영되는데 **AI 구단은 기본 레벨 0** 이라, 플레이어 쪽만 강해진다:
> 시즌 1 우승률 **16.5% → 20.5%**(목표 ≤20% 를 벗어난다), 시즌 2 **50.5% → 70.0%**, 시즌 3 **57.0% → 75.5%**.
> 스킬 시스템이 확정되면 **사다리 g 를 다시 캘리브레이션해야 한다** — 이 문서는 그 전 상태를 기록한 것이다(D.2 열린 이슈).

카드 풀이 늘어 로스터가 계속 채워지자 후반 지정 스카우트 수요가 오히려 줄어(시즌 5 16.2회 → 시즌 15 8.6회)

## A.2 시즌 캘린더와 외곽 루프

### A.2.1 매치데이 = 세션 1회

**매치데이 하나가 플레이 세션 하나**다. 이것이 리그와 육성을 묶는 단위다.

```
[매치데이 N 시작]
  → 스카우트(보유 티켓 소진, 0~2회)            ~1분
  → 한계돌파(조각 30 이상이면)                  ~30초
  → 육성 1회 (스태미나 30)                      ~10분 (스킵 2분 / 자동 3.6분)
  → 라인업·전술 점검                            ~1분
  → 매치데이 경기 (자동 1분 / 관전 5분)          1~5분
  → 결과·보상 → 순위표 갱신
[매치데이 N+1 …]
```

| 항목 | 값 | 근거 |
|---|---|---|
| 매치데이당 육성 | **1회 (기준선)** | 시간 예산과 사다리 밸런스(A.4)를 이 값에 맞췄다 |
| 프리시즌 캠프 | 시즌 1 개막 전 **2회**만 | 튜토리얼 + 첫 로스터 확보. 시즌 2 이후의 프리시즌은 매치데이 루프에 흡수 |
| 시즌 1 총 육성 | **16회** (2 + 14) | 시뮬 기준선 |
| 매치데이 소요 | 수동 **≈ 15분** / 스킵·자동 **≈ 5분** | 육성 9.2분(training-mode 1.2) + 경기·기타 |
| 한 시즌 소요 | 수동 **≈ 3.5~4시간** / 자동 **≈ 1.2시간** | 14 매치데이 |
| 한 시즌 실시간 | **1~2주** (하루 1~2 매치데이) | GDD 1절 "중기 루프 1~2주" |

### A.2.2 스태미나와의 정합 (열린 이슈)

`training-mode.md` 10절: 육성 1회 = **스태미나 30**, 상한 **120**, 회복 **6분당 1**(하루 240).

| 계산 | 값 |
|---|---|
| 하루 자연 회복 | 240 (+ 일일 미션 30, 정식) = **270** |
| 이론상 하루 육성 | 270 / 30 = **9회** |
| 상한 120 의 제약 | 한 번 접속에 최대 4회 연속. 9회를 다 쓰려면 하루 3회 이상 접속 |
| 무과금 일일 기대 (training-mode 10절) | **3~4회** |

**즉 스태미나는 매치데이당 육성 1회를 강제하지 않는다.** 하루에 매치데이 1개만 진행해도 스태미나가 남고, 열심히 하는 유저는 매치데이당 3~4회 육성할 수 있다. 이것이 이 설계의 가장 큰 미해결 지점이다.

| 대응안 | 내용 | 판정 |
|---|---|---|
| **(a) 매치데이 게이팅** | 매치데이를 넘겨야 다음 육성 슬롯이 열린다(육성 1회/매치데이 하드 캡) | 스태미나가 무의미해지고 "하고 싶은데 못 한다"의 불만. **기각** |
| **(b) 남는 스태미나를 다른 소비처로** | 재육성·평가전 반복·연습경기·소재 던전에 스태미나를 쓰게 하고, **리그 로스터에 반영되는 육성은 매치데이당 1회만 대표 갱신 가능** | 유력. 대표 인스턴스 갱신에 쿨다운을 두는 셈 |
| **(c) 그냥 둔다** | 헤비 유저가 빨리 강해지는 것을 허용. 사다리 g 를 유저 진척도에 연동 | 라이브 서비스에서는 흔한 해법이지만 g 를 진척도 연동하면 "사다리" 서사가 깨진다 |

근사 모델에 매치데이당 육성 2회(라이트-헤비 중간) 시나리오를 넣어 영향을 측정했다: 같은 모델 안에서
**시즌 1 우승률 1% → 6%, 4강 7% → 18%, 시즌 3 우승률 16% → 32%** (B.3.5 표). 사다리가 대략 한 시즌 앞당겨진다.
(절대값은 근사라 엔진과 다르다 — 배율만 읽을 것.) **(b) 를 1순위로 두되 프로토타입에서는 (c) 로 두고 실측한다**(D.1 검증 항목).

### A.2.3 시즌 경계

```
매치데이 14 종료
  → [정규 시즌 결산] 최종 순위표 · 개인 기록(득점/블로킹/서브/리시브 1위) · 내 팀 시즌 리포트
  → [포스트시즌] (4위 이내일 때만 플레이, 아니면 관전/스킵 가능 — 보상은 순위 보상만)
  → [시즌 결산 화면] A.5.2
  → [사다리 상승] g += 11%p (시즌 4 부터는 상한 80% 라 증가 0), AI 구단 스탯 재계산, 연습생 7명 신규 세대로 교체
  → [프리시즌] 육성 1회 + 스카우트
  → 다음 시즌 매치데이 1
```

### A.2.4 라이브 서비스 시즌과의 대응

| 게임 내 | 라이브 운영 | 비고 |
|---|---|---|
| 블룸 리그 1시즌 (14 매치데이, 실시간 1~2주) | **시즌패스 1주기의 절반** | 패스는 2주 단위가 흔하다 |
| 시즌 사다리 g | **계정별로 진행**(서버 저장). 유저마다 시즌 번호가 다르다 | 랭킹은 g 가 아니라 "시즌 번호 + 승점"으로 매칭 |
| 시즌 랭킹 | 같은 시즌 번호끼리 승점·세트 득실 랭킹 | 사다리가 개인 진척도라 시즌 번호를 리그로 나눈다 |
| 픽업·이벤트 | **실시간 캘린더**(2~4주). 게임 내 시즌과 무관 | 픽업이 리그 시즌에 묶이면 운영이 경직된다 |

**핵심 결정: 게임 내 시즌은 개인 진척도, 라이브 시즌(패스·픽업·랭킹 기간)은 실시간 캘린더로 분리한다.** 두 개를 묶으면 늦게 시작한 유저가 시즌 1을 건너뛰어야 하거나, 빠른 유저가 기다려야 한다.

## A.3 AI 구단 규칙

### A.3.1 시즌 사다리 — 성장률 g

`prototype-play.md` 6.4 #1 의 관찰이 근거다. `players.json` 초기치 그대로면 연습생만으로도 6% 이기고 졸업생 6명이면 70~90% 이긴다. 잠재력 60% 성장이면 8회 육성해도 6~28%. 사다리는 이 구간을 시즌 단위로 늘려 놓기 위한 장치다.

```
실효 스탯(선수 p, 시즌 n) = round( clamp( stats_p + g(n) × (potential_p − stats_p), 0, 100 ) )
```

**g(n) = `[0.52, 0.63, 0.74, 0.80, 0.80, …]`** (`web/engine/game.js` `SEASON_GROWTH`)

| 시즌 n | g(n) | 6구단 라인업 OVR 평균 | 최약(라온) | 최강(연화) | 전 시즌 대비 |
|---|---|---|---|---|---|
| 1 | **52%** | **68.7** | 66.6 | 70.3 | — |
| 2 | **63%** | 71.3 | 69.2 | 72.8 | +2.6 |
| 3 | **74%** | 73.6 | 71.6 | 75.0 | +2.3 |
| 4+ | **80% (상한)** | 74.9 | 73.0 | 76.3 | +1.3 → 0 |

(구단별 시즌 1: 연화 70.3 · 가온 69.5 · 해솔 69.3 · 적동 69.2 · 태령 67.6 · 라온 66.6. 라인업 = 선발 6 + 리베로 = 로스터 7명 전부라 로스터 평균과 같다.
측정: `node web/parity.mjs` ①-b 와 같은 정의, `clubTeamState` + 포지션 가중 OVR.)

**왜 v0.1 의 `35 / 48 / 58 / 66 / 72 / 76%` 를 버렸나.** 그 값은 두 가지를 전제로 잡혔다 —
① 승률을 실제 `MatchSimulator` 가 아니라 `sigmoid(0.235 × ΔOVR)` 로 근사했고,
② A.3.5(스카우트된 선수의 원소속 구단 결원)를 **시뮬에 넣지 않았다**(v0.1 이 스스로 D.1 E11·D.2 에 적어 둔 한계다).
둘 다 실제로 구현된 엔진에 초기값을 그대로 얹으니 **시즌 1 정규 승률 59% · 우승률 38%** 가 나왔다 —
목표(40~50% · ≤20%)를 크게 벗어난, "첫 시즌부터 우승하는" 난이도다. `web/season-check.mjs` 로 재캘리브레이션한 것이 위 표다.
**성장 수식은 건드리지 않았다**: g 를 v0.1 값으로 고정하면 옛 표가 그대로 재현된다(g 35% → 65.30 / 58% → 70.31 / 80% → 74.91).

증가폭은 여전히 **체감**한다(+11 → +11 → +6 → 상한). 이유는 A.4 에 있다: 플레이어 로스터의 성장도 체감하므로 사다리가 선형이면 시즌 5 이후 영원히 못 이기거나 영원히 지지 않는다.
다만 v0.1 이 7시즌에 걸쳐 오르던 것이 **시즌 4 에 상한에 닿는다** — 그 결과가 A.4.3 의 열린 이슈다.

**같은 선수, 두 얼굴.** `world.md` 1.2 의 "공개 스카우트 명단" 프레임을 규칙으로 굳힌다.

| 맥락 | 능력치 | 화면 표기 |
|---|---|---|
| 스카우트 대상(플레이어가 뽑는 카드) | `stats` = **신인 초기치** | "원소속: 연화 크레인즈 · 등록: 육성 명단" |
| 리그 상대(원소속 구단 소속으로 출전) | `stats + g × (potential − stats)` = **성장 버전** | 구단 로스터 화면에 실효 스탯 표시 |
| 내 팀에 편입된 뒤 | 육성 졸업 확정치(`PlayerInstance.FinalStats`) | 유니폼 레이어 교체(GDD 9.2) |

서사: **여섯 구단은 매 시즌 유망주를 공개 명단에 올려야 하지만, 명단에 올린 선수를 자기들도 계속 키운다.** 플레이어가 소이든을 스카우트하는 것은 "연화가 아직 꽃피우지 못한 원석"을 데려오는 것이고, 리그에서 마주치는 소이든은 "연화에서 g만큼 자란 소이든"이다. 같은 선수가 양쪽에 존재하는 것이 아니라, **스카우트되는 순간 원소속 구단의 로스터에서 빠진다**(A.3.5).

### A.3.2 AI 구단 라인업

| 항목 | 규칙 |
|---|---|
| 로스터 | `data/players.json` 의 해당 `teamId` **7명 고정**(S1 · OH2 · OP1 · MB2 · L1) |

### A.3.5 스카우트된 선수의 원소속 구단 처리

플레이어가 카드를 스카우트하면 그 선수는 **원소속 구단 로스터에서 빠진다.** 구단은 7명이므로 빈 자리가 생긴다.

| 규칙 | 내용 |
|---|---|
| 결원이 생기는 시점 | **졸업시켜 대표 인스턴스가 된 순간**(엔진 `departedCardIds` = `state.instances` 기준). 뽑아서 보유만 하고 아직 안 키운 카드는 원소속에서 계속 뛴다 |
| 결원 보충 | 그 구단의 **동일 포지션 육성 선수**(제네릭 N 카드, `RandomPlayerGenerator` overall = 해당 구단 평균 **− 4**)로 자동 대체 |
| **결원 보충 상한 (v0.3)** | 육성 선수로 버티는 것은 **구단당 4명까지.** 5번째 결원부터는 **즉시전력 영입**(포지션 가중 OVR = 구단 사다리 평균 **− 2.0**, 나이 20, "(영입)" 배지) |
| 기준이 되는 "구단 평균" | **원 로스터 7명의 스탯 평균**으로 고정한다. 결원이 늘어도 대체 선수 강도가 따라 내려가지 않게 하기 위해서다 |
| 표기 | 구단 로스터에 "(육성 선수)" 배지. 리그 순위표 옆 "이적 현황" 탭에서 확인 |
| 밸런스 영향 | 강한 카드를 뽑을수록 그 구단이 약해진다 = **뽑기 성공이 리그에서 두 번 보상된다** |
| 되돌림 | 방출해도 원소속으로 돌아가지 않는다(조각으로 환급) |

**−8 → −4 로 완화한 이유.** v0.1 의 −8 은 이 규칙을 **시뮬에 넣지 않은 채 적은 추정치**였다.
실제로 켜 보니 시즌 1 말에 평균 11장 남짓이 6구단에서 빠져나가고, −8 에서는 AI 평균 OVR 이
**65.3 → 63.6 (−1.7) 으로 시즌 중에 계속 내려갔다**(당시 사다리 g=35% 기준).
사다리는 "예측 가능한 벽"(A.3.2)이어야 하는데, 플레이어가 강해질수록 벽이 같이 무너져 시즌 후반이 급격히 쉬워졌다.

**−4 로 확정한 뒤의 실측**(시즌 1 · n=60 · g=52%):

| 시점 | 6구단 평균 OVR | 최약~최강 | 격차 |
|---|---|---|---|
| 결원 없음(기준) | **68.73** | 66.6~70.3 | 3.7 |
| 시즌 1 개막 (프리시즌 육성 후) | 68.39 | — | — |
| 시즌 1 종료 (졸업 카드 평균 **11.1장** 이탈) | **67.90** | 64.9~70.0 | **5.1** |

시즌 중 하락이 −1.7 에서 **−0.83** 으로 줄었다. "뽑기 성공이 두 번 보상된다"는 서사는 남기되(격차가 3.7 → 5.1 로 벌어진다),
벽이 시즌 중에 붕괴하지는 않는 값이다.

**단위 주의.** −4 는 **스탯 10종의 단순 평균** 공간에서 주는 값이고(`generatePlayer` 의 `overall` 인자),
그것이 포지션 가중 OVR 공간에서는 **−7.4** 로 나타난다(g 35~80% 구간에서 −7.32 ~ −7.53, 구단×선수 42쌍 실측).
`economy_sim.py` 는 OVR 공간에서 돌아가므로 `vacancy_ovr_delta = -7.4` 를 쓴다.

이 규칙은 서사(공개 스카우트 명단 → 실제로 데려간다)와 게임성(SSR 획득의 체감 배증)을 동시에 만든다.
**v0.2 에서 엔진·시뮬 양쪽에 구현됐다**(v0.1 의 "미반영" 단서는 해소됐다).

**왜 v0.3 에서 상한 4를 붙였나 — 이중 보상이 리그를 비웠다.**
−4(= OVR −7.4)는 시즌 1 말 기준(구단당 결원 1.9명)으로 잡은 값이다. 그런데 결원은 시즌마다 누적된다:

| 시즌 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 플레이어가 가져간 카드 (42중) | 11.2 | 17.3 | 23.3 | 26.4 | 29.0 | 30.4 | 31.9 | **33.0** |
| 구단당 결원 (7명 중) | 1.9 | 2.9 | 3.9 | 4.4 | 4.8 | 5.1 | 5.3 | **5.5** |
| AI 실전 평균 OVR — 상한 없음 | 67.9 | 69.8 | 71.3 | 71.9 | 71.2 | 70.7 | 70.5 | **70.2** |
| AI 실전 평균 OVR — **상한 4 (v0.3)** | 67.9 | 69.8 | 71.4 | **72.3** | **71.9** | **71.8** | **71.6** | **71.4** |

상한이 없으면 시즌 8 의 6구단은 로스터 7명 중 5.5명이 육성 선수다 — 사다리 표의 74.9 가 실전에서는 **70.2** 가 된다.
"뽑기 성공이 두 번 보상된다"가 시즌 5 부터는 "리그가 사라진다"가 된 것이다.
상한 4는 **시즌 1~3 을 전혀 건드리지 않으면서**(그때는 구단당 결원이 3.9명 이하라 상한에 닿지 않는다) 시즌 4 부터만 작동한다.
서사도 자연스럽다 — 주전 절반이 빠져나간 프로 구단은 육성 선수로 버티지 않고 외부에서 즉시전력을 영입한다.

### A.3.6 선수 노화 · 전성기 · 은퇴 (v0.3 신설)

`data/players.json` 의 `age`(18~24) 를 v0.2 까지는 화면에만 썼다. v0.3 은 이것을 **판정에 쓰는 상태**로 승격한다.
목적은 하나다 — **플레이어 로스터의 무한 상승을 구조적으로 막는 것**(A.4.3 · A.4.4).

#### A.3.6.1 나이는 저장하지 않고 파생한다

```
나이(선수 p, 시즌 n) = p.age + (n − 1)
```

42명 전원이 같은 속도로 늙는다. 상태를 늘리지 않으므로 **세이브 포맷이 바뀌지 않고**(구 세이브 그대로 로드된다),
같은 시드는 같은 나이를 준다(C.4 결정성). 연습생 7명은 매 시즌 새 세대로 교체되므로 항상 19세로 고정한다.

#### A.3.6.2 곡선

| 구간 | OP · MB | OH | S · L | 실효 스탯 배수 |
|---|---|---|---|---|
| 성장기·전성기 | ~25세 | ~26세 | ~27세 | **1.000** |
| 하락 1년차 | 26 | 27 | 28 | **0.930** (−7.0%) |
| 하락 2년차 | 27 | 28 | 29 | 0.925 |
| 하락 3년차 | 28 | 29 | 30 | 0.920 |
| 하락 4년차 | 29 | 30 | 31 | 0.915 |
| 하락 5년차 | 30 | 31 | 32 | 0.910 |
| **은퇴** | **31세** | **32세** | **33세** | — (코트에 서지 못한다) |

```
배수 = clamp( 1 − 0.07 − 0.005 × (초과연수 − 1),  0.70,  1.0 )       # 초과연수 ≥ 1
실효 스탯 = round( 사다리/졸업 스탯 × 배수 )
```

**곡선의 모양 — 계단 한 번, 그다음은 평평.** 전성기를 넘긴 첫 해에 **−7%** 가 한 번에 오고, 그 뒤로는 연 −0.5%p 로 거의 평평하다.
근거는 두 가지다. ① 실제로 배구에서 먼저 빠지는 것은 점프력·스피드이고, 기술·경기 읽기·서브는 오히려 늘어 신체 저하를 상당 부분 상쇄한다 —
베테랑은 "완만하게 계속 나빠지는" 것이 아니라 "한 단계 내려앉은 뒤 오래 유지하다가 은퇴한다". ② 밸런스상으로도 이 모양이어야 고원이 된다:
연 −1.5%p 로 계속 깎으면 시즌 4~6 은 그대로인데 시즌 8 만 무너진다(실측 우승률 60/63/54/48/**32%**, 목표 하한 40% 미달).
**시즌마다 늘어나는 것은 "얼마나 깎이느냐"가 아니라 "몇 명이 하락기에 들어갔느냐"** 이고, 고원을 만드는 것은 후자다
(라인업 7슬롯 중 하락기 슬롯: 시즌 3 **0.11** → 4 0.73 → 5 1.19 → 6 2.07 → 7 3.14 → 8 **3.85**).

**포지션별 차이.** 세터·리베로 +2년, 아웃사이드 +1년, 아포짓·미들 기준. 점프·파워 의존도가 높을수록 선수 생명이 짧다는
실제 배구의 경향을 그대로 옮긴 것이다(리베로·세터는 30대 중반까지 뛰는 사례가 흔하다). 게임적으로도 의미가 있다 —
세터·리베로는 로스터에서 오래 버티는 축, 미들·아포짓은 계속 갈아 끼우는 축이 된다.

**나이 숫자는 실제 배구보다 압축돼 있다 — 그리고 그건 의도다.**
실제 여자 배구의 전성기는 대략 24~29세, 은퇴는 30~34세다. 이 게임의 카드는 18~24세로 시작하고
검증 구간이 8시즌(= 8년)이므로, 실제 곡선을 그대로 쓰면 **노화가 검증 구간 안에서 거의 작동하지 않는다.**
실측으로 확인한 사실이다 — 전성기 끝을 26세로 두면 하락률을 2.5%/년에서 5.5%/년으로 두 배 넘게 올려도
시즌 4~6 우승률이 65/73/80% → 63/70/70% 로밖에 내려가지 않는다. **시즌 4~6 에는 애초에 전성기를 지난 선수가 거의 없기 때문**이다.
그래서 "전성기가 언제 끝나는가"를 앞당겨 곡선을 압축했다. 표기상으로는 **전성기 22~25/26/27세**로 읽으면 된다.

#### A.3.6.3 플레이어 쪽 규칙

| 규칙 | 내용 |
|---|---|
| 적용 지점 | **코트에 서는 순간.** 졸업 인스턴스의 `finalStats` 자체는 그대로 두고, 라인업·경기에 들어갈 때 배수를 곱한다(A.3.1 "같은 선수, 두 얼굴"과 같은 방식) |
| 자동 편성 | `autoLineup` 은 **나이가 반영된 스탯**으로 고른다 → 하락한 노장이 자동으로 밀려나고 젊은 카드가 올라온다 |
| 재육성 | 나이는 **초기화되지 않는다.** 시즌 6 에 26세 카드를 다시 키우면 결과 인스턴스도 26세다 — "다시 키워서 젊게 만든다"는 우회로가 없다 |
| 은퇴 | 로스터에서 빠져 경기에 못 나온다. 그 카드는 **스카우트 명단에서도 사라진다**(다시 뽑을 수 없다) |
| 은퇴 후 | 인스턴스는 사라지지 않고 **서포터(코치)로 남는다** — 육성 서포터 후보에 계속 뜬다. 손실이 아니라 역할 변경이 되게 한 장치 |
| 시즌 1~3 보호 | 전성기 끝이 가장 이른 OP·MB 도 25세다. 카드 최고령이 24세이므로 **시즌 1~2 에는 하락자가 0명**, 시즌 3 에도 라인업 7슬롯 중 평균 0.11슬롯뿐이다. **시즌 1 에 뽑아 키운 선수는 최소 7시즌(가장 어린 카드는 그 이상) 주전으로 뛴다** |

#### A.3.6.4 AI 구단 쪽 규칙 — 세대교체

AI 6구단에도 **같은 노화 곡선**이 적용된다. 다만 프로 구단은 노쇠한 선수를 붙잡지 않는다:

```
AI 선수의 나이 배수 < 1.0  →  그 시즌 즉시 같은 자리의 신인으로 교체
   신인: 나이 20 · 제네릭 N 카드 · 포지션 가중 OVR = 떠난 선수의 사다리 OVR (동일)
   시드 = H(clubId, cardId, 세대) — 결정적
```

결과적으로 **구단 평균 OVR 은 사다리 값에 고정된다.** 결원이 없을 때 68.73 / 71.31 / 73.60 / 74.91 …
시즌 12 까지 74.9 ± 0.05 (`node web/parity.mjs` ③). 즉 **A.4.3 의 "성장률 상한 0.80 = 의도된 종착점" 전제는 바꾸지 않았다.**
바뀐 것은 반대쪽이다 — 이제 **플레이어도 멈춘다.**

| 시즌 | 4 | 6 | 8 | 10 | 12 |
|---|---|---|---|---|---|
| 6구단 42명 중 신인으로 교체된 수 | 2 | 12 | 23 | 39 | 42 |
| 결원 없을 때 구단 평균 OVR | 74.91 | 74.91 | 74.92 | 74.92 | 74.91 |

리그가 눈에 보이게 세대교체를 한다(시즌 12 면 개막 로스터가 전부 새 얼굴이다) — 이것이 "리그가 살아 있다"는 감각을 만든다.

### A.4.2 왜 사다리가 필요한가 — 수식

플레이어 라인업 OVR 을 `P(n)`, AI 구단 평균을 `C(n) = f(g(n))` 라 하자. 승률은 밸런스 리포트 9절(팀 overall 57/62/67/72/77 → 8.5/23.6/49.5/76.3/90.8%)을 로지스틱으로 회귀한 근사식이다.

```
승률(경기) ≈ sigmoid( 0.235 × (P − C) + 홈보정 )
```

`0.235` 는 **OVR 1 차이 ≈ 승률 5.8%p**(동급 근방)를 뜻한다. OVR 5 차이면 76%, 10 차이면 91%.

플레이어의 성장은 **로스터 7슬롯의 최댓값 갱신**이라 강하게 체감한다:

```
P(n) ≈ (1/7) Σ_slot  max( 그 포지션에서 보유한 인스턴스들의 OVR ,  연습생 46.0 )
```

연습생 라인업 OVR 은 실측 **시즌 1 = 46.00**, 시즌당 +0.83, 고원 49.7 이다
(`fillerOverall` 44 + 시즌당 1, 상한 48 을 포지션 가중 OVR 로 환산한 값).

시즌 1 개막에 4개 슬롯이 연습생이므로 **첫 몇 회 육성이 슬롯당 +15~20 OVR** 을 준다(라인업 OVR 56.1 → 67.9).
그다음부터는 이미 R 카드가 앉은 자리를 SR 로 바꾸는 +9 남짓뿐이고, 그마저 카드 운에 걸린다.

**아래는 전부 엔진 실측**(개막 = 프리시즌 육성 후 매치데이 1 직전 / 중반 = 매치데이 7 / 종료 = 결산 시점).
시즌 1~3 은 n=200, 시즌 4~5 는 n=60.

| 시즌 | 내 라인업 P (개막→종료) | AI 평균 C | 개막 시점 격차 | 종료 시점 격차 |
|---|---|---|---|---|
| 1 | 56.1 → **69.8** (+13.7) | 68.7 | **−12.6** | **+1.1** |
| 2 | 71.1 → **73.1** (+2.0) | 71.3 | −0.2 | +1.8 |
| 3 | 73.9 → **75.2** (+1.3) | 73.6 | +0.3 | +1.6 |
| 4 | 75.5 → **76.4** (+0.9) | 74.9 (상한) | +0.6 | +1.5 |
| 5 | 77.1 → **77.7** (+0.6) | 74.9 (상한) | +2.2 | **+2.8** |

시즌 간 증분으로 다시 보면:

| 전이 | 플레이어 ΔP (종료→종료) | AI ΔC | 종료 시점 격차 변화 |
|---|---|---|---|
| 1→2 | 69.8 → 73.1 = **+3.3** | 68.7 → 71.3 = +2.6 | +1.1 → **+1.8** |
| 2→3 | 73.1 → 75.2 = **+2.1** | 71.3 → 73.6 = +2.3 | +1.8 → **+1.6** |
| 3→4 | 75.2 → 76.4 = **+1.2** | 73.6 → 74.9 = +1.3 | +1.6 → **+1.5** |
| 4→5 | 76.4 → 77.7 = **+1.3** | 74.9 → 74.9 = **0** | +1.5 → **+2.8** |

**설계 의도는 시즌 3까지 성립한다.** ΔP 가 +3.3 → +2.1 → +1.2 로 줄고 ΔC 가 +2.6 → +2.3 → +1.3 으로 따라 줄어,
격차가 +1.1 ~ +1.8 의 좁은 띠에 머문다 — "우승은 하지만 매 시즌 싸워야 하는" 상태다.

**깨지는 것은 시즌 4 부터다.** g 가 상한 80% 에 닿아 ΔC 가 0 이 되는데 ΔP 는 아직 +1.3 이라, 격차가 +1.5 → +2.8 로 벌어진다.
v0.1 은 g 를 7시즌에 걸쳐 올려 이 지점을 시즌 6~7 로 미뤘지만, v0.2 의 사다리는 시즌 4 에 상한에 닿는다(A.4.3).

> v0.1 의 이 표는 승률 로지스틱 근사 위의 **추정치**였고(P 55.0 → 67.5 등), 위 값과는 다르다.
> 특히 v0.1 이 예상한 "격차 +2.9~+3.3 고원"은 실제로는 시즌 3까지 **+1.1~+1.8** 로 더 팽팽하다.

> **v0.3 주.** 위 두 표(P·C·격차)는 **v0.2 시점의 값**이고, 이 절이 지적한 "시즌 4 부터 깨진다"가 v0.3 이 고친 문제다.
> v0.3 의 같은 지표는 A.4.3 의 표를 볼 것 — ΔP 가 시즌 5 부터 **음수**가 되면서(노화) 격차가 다시 닫힌다.
> 이 절의 수식(승률 ≈ `sigmoid(0.235 × (P − C))`)과 "플레이어 성장 = 슬롯별 최댓값 갱신"이라는 구조 설명 자체는 그대로 유효하다.
> 다만 실전 격차를 볼 때는 **결원이 반영된 AI 실전 OVR**(A.4.3 표)을 써야 한다 — 결원 없는 사다리 값 74.9 는 시즌 4 이후 실전과 3 이상 벌어진다.

### A.4.3 사다리가 만드는 압박 — 그리고 상한 0.80 이라는 종착점 (v0.3 개정)

시즌 4 이후 g 가 상한(80%)에 닿으면 AI 는 더 이상 강해지지 않는다. **이 전제는 v0.3 에서도 바꾸지 않았다** —
무한 사다리는 F2P 유저를 이탈시키고, 잠재력 88% 짜리 AI 는 카드 개성을 지운다. 리그 이후의 도전 축은
**PvP 랭킹·픽업 카드·완성도 갱신**으로 넘긴다는 결정(GDD 6·8절)도 그대로다.

**v0.2 가 틀린 것은 이 전제가 아니라, 전제의 절반만 본 것이었다.** "AI 가 멈춘다"까지는 맞는데,
그 옆에 **"그러면 플레이어도 멈추는가?"** 를 묻지 않았다. 실측은 아니었다 — g 가 멈춘 뒤에도
내 라인업 OVR 은 시즌 5 76.4 → 시즌 8 79.7 로 계속 올랐고 우승률은 65 → 96.7% 로 단조 증가했다.

사다리를 손대는 대신(그건 AI 쪽 전제를 깨는 일이다) 선수 개인에게 수명을 준다(A.3.6).
그러면 두 곡선이 같은 이유로 멈춘다: AI 는 상한 0.80 에서, 플레이어는 로스터의 노화에서.

#### A.4.3.1 채택안과 기각안

과제로 받은 후보 (a)~(d) 를 전부 검토했고, 기획 결정으로 **(b) 노화·전성기·은퇴를 채택**했다.
(a) 와 골드 소비처는 노화만으로 목표에 닿지 않는 구간에서 **보완 수단**으로 최소한만 썼다.

42장 풀 전체가 같이 늙으므로 "더 좋은 카드로 갈아탄다"는 탈출구도 시간이 지나면 좁아진다.

**설계 원칙: 유료 재화(젬)는 육성의 결과에 직접 개입하지 않는다.** 젬으로 살 수 있는 것은 "더 많은 시도"(티켓·스태미나)이지 "더 좋은 결과"(부상 방지권·컨디션 드링크)가 아니다 — `training-mode.md` 10·13절의 P2W 논의를 그대로 계승한다(B.5).

### B.1.2 왜 골드를 새로 두는가

프로토타입에는 티켓과 조각뿐이라 **"돈이 있는데 쓸 데가 없다/티켓이 없어 아무것도 못 한다"의 두 상태만** 존재했다. 골드는 세 가지를 한다.

1. **포지션 지정 스카우트의 가격표.** 티켓 1 + 골드 1,200. 티켓만으로 지정할 수 있으면 일반 스카우트를 아무도 안 쓴다.
2. **경기의 즉시 보상.** 티켓은 12조각(경기 2~4회)을 모아야 나오지만 골드는 매 경기 들어온다 — 패배해도 손에 뭔가 남는다(프로토타입 피드백의 "패배 조각" 을 계승·확장).
3. **장비·굿즈(GDD 7절)의 화폐.** 정식에서 로스터 강화의 비가챠 축.

엔진 실측 3시즌 뒤 골드 잔액 **10,400** — 소비처가 포지션 지정뿐이라 초반에는 남는다(시즌 1 말 8,693 / 2 말 9,108 / 3 말 10,400).

> **v0.5 주 — 아래 v0.3 절의 결론은 신인 세대(v0.4) 도입으로 무효가 됐다.** 카드 풀이 42 → 87장으로 늘면서
> 후반 지정 스카우트 수요가 오히려 줄어(시즌 5 16.2회 → 시즌 15 8.6회) 골드가 다시 쌓였고,
> 시즌 15 잔액이 **31,157** 이 됐다. **v0.5 는 소비처를 새로 만들어(B.6) 시즌 4~15 를 8.4k~11.4k 평탄대에 묶었다.**
> `골드 3.` 의 "장비·굿즈"는 여전히 정식 과제이지만, 프로토타입 범위의 소비처는 이제 셋 더 있다.

**v0.3: 장기 축적 문제는 노화가 해소했다.** v0.2 의 골드는 시즌이 갈수록 무한히 쌓였다(시즌 8 잔액 **46,120**) —
로스터가 완성되면 포지션 지정 스카우트를 쓸 이유가 없어지기 때문이다. 노화·은퇴(A.3.6)가 들어오면서
**자리가 계속 비므로 지정 스카우트 수요가 끊기지 않는다**:

| 시즌 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 골드 잔액 — v0.2 | 8,695 | 9,124 | 10,694 | 16,473 | 19,767 | 29,005 | 36,713 | **46,120** |
| 골드 잔액 — **v0.3** | 8,693 | 9,108 | 10,400 | **15,070** | 11,996 | 13,155 | 11,589 | **8,712** |

시즌 4 에서 정점을 찍고 내려온다. **새 소비처를 발명하지 않고 기존 소비처의 수요를 늘려서 푼 것**이라,
장비·굿즈(GDD 7절)·보관함 확장·연습생 리롤은 여전히 정식 범위의 과제로 남는다(D.2).

**v0.5 에서 결국 소비처를 발명해야 했다.** 위 논리는 "자리가 비면 지정 스카우트를 쓴다"에 기대는데,
신인 세대가 그 자리를 메워 주면서 전제가 무너졌다. 하나뿐인 소비처의 수요에 경제 전체를 걸면
그 수요를 바꾸는 다른 시스템이 들어올 때마다 경제가 흔들린다 — **B.6 은 그래서 서로 성격이 다른 소비처 셋을 두었다**
(플레이어가 사는 것 둘 + 자동으로 나가는 것 하나).

### B.2.1 종류별 비용·확률

| 종류 | 비용 | 풀 | 확률 | 천장 | 범위 |
|---|---|---|---|---|---|

| 10연 (모든 종류) | 단가 × 10 | — | 동일 | **SR 이상 1장 보장**(10연 내 SR+ 가 없으면 10번째를 SR 로) — **미구현**, 현재 UI 의 10연은 단차 10회일 뿐이다 | 정식 |

**확률을 R 80 / SR 17 / SSR 3% 에서 바꾸지 않는 이유.** `prototype-play.md` 6.4 #2 는 "R 80% 가 로스터 성장을 R 카드에 묶는다(3시드 24회에서 SSR 0장, 첫 SSR 기대 33회)"고 지적했다. 확률을 올리는 대신 **천장 + 포지션 지정 + 조각 가치**로 풀었다. 이유:

- 확률 자체를 올리면(예: SSR 5%) 표기 확률이 경쟁작 대비 높아 보이지만 **분산은 그대로**라 "60회 뽑았는데 없다"는 유저는 여전히 생긴다. 천장은 분산의 꼬리를 자른다.
- R 카드가 무가치한 것이 근본 문제였는데, 이는 **중복 R 이 곧바로 한계돌파 1단계**가 되는 것과 **포지션 지정으로 R 을 원하는 자리에 배치**하는 것으로 해소된다(B.4). 실측 3시즌 누적 한계돌파 26.0단계.
- 국내 확률형 아이템 표시 의무상 확률과 천장은 모두 공개해야 하므로, "천장 있는 3%" 가 "천장 없는 5%" 보다 설명하기 쉽고 유저 신뢰도 높다.

### B.2.2 천장 규칙

```
매 뽑기마다:
  pitySR  += 1
  pitySSR += 1
  if pitySSR >= 60:  결과 = SSR           # 하드 천장
  elif pitySR >= 10: 결과 = SR 또는 SSR    # SSR 비중 = 3/(3+17) = 15%
  else:              결과 = 기본 확률표
  결과가 SR 이상이면 pitySR = 0
  결과가 SSR      이면 pitySSR = 0
```

| 규칙 | 실효 등급 확률 | SSR 간격 평균 | SSR 간격 p50 / p90 / 최대 | SR+ 간격 p90 / 최대 |
|---|---|---|---|---|
| 천장 없음 | R 79.9 / SR 17.1 / SSR 3.09% | 32.4 | 23 / 73 / **260** | 11 / 45 |
| SR 10 만 | R 77.5 / SR 19.1 / SSR 3.43% | 29.1 | 21 / 65 / **236** | 10 / 10 |
| **SR 10 + SSR 60 (채택)** | **R 77.2 / SR 18.9 / SSR 3.87%** | **25.9** | 21 / 60 / **60** | 10 / 10 |
| SR 10 + SSR 50 (대안) | R 77.1 / SR 18.8 / SSR 4.10% | 24.4 | 21 / 50 / 50 | 10 / 10 |

(120,000회 뽑기, `economy_sim.py --only new`)

**천장 카운터는 일반과 포지션 지정이 공유한다.** 이유: 분리하면 "천장 직전에는 포지션 지정을 쓰면 손해"라는 역-최적화가 생겨 유저가 원하는 포지션을 못 뽑게 된다. 픽업만 별도 카운터를 두는 것은 업계 표준이고, 픽업 종료 시 카운터 이월 여부는 정식 정책으로 미룬다(D.2).

### B.2.3 UI 표기 규칙 (국내 확률형 아이템 표시 의무 전제)

「게임산업진흥에 관한 법률」의 확률형 아이템 표시 의무를 전제로 다음을 **게임 내와 공식 홈페이지 양쪽**에 표기한다. (법령 해석·최종 문구는 출시 전 법률 검토 필요 — D.2)

| 위치 | 표기 내용 |
|---|---|
| 스카우트 화면 상단 상시 | "R 80% · SR 17% · SSR 3%" + [확률 자세히] 버튼 |

### B.2.4 중복 처리와 한계돌파

**구현된 규칙 (v0.2):**

```
중복 카드 획득 → 그 카드의 한계돌파 +1 단계 (즉시, 최대 5단계 = 전 스탯 potential +15)
조각 12개    → 스카우트 티켓 1        (조각은 경기 보상·방출에서만 나온다)
```

**v0.1 의 "중복 → 희귀도 조각 10 → 30개마다 1단계"는 채택하지 않았다.** 두 가지 이유다.

1. 엔진의 조각 풀은 **하나**다. 희귀도별로 나뉘지 않아 "R 조각은 R 카드만 돌파" 규칙이 성립하지 않고, 5:1 상위 변환도 없다.
2. 조각 풀이 하나인 채로 중복에 조각 10 을 주면 **조각이 곧 티켓**이 된다(10 조각 = 티켓 0.83).
   즉 뽑기 1회가 뽑기 0.83회를 재생산하는 되먹임이 생겨, 실측에서 **시즌 2 스카우트가 63회**까지 폭주했다.
   중복이 이미 한계돌파 1단계를 통째로 주고 있으므로 조각까지 얹을 이유도 없다.

- **한계돌파는 카드 단위**(인스턴스가 아님). 돌파 후에는 **재육성해야 반영된다** — "상한이 올랐으니 다시 키운다"가 `training-mode.md` 8.6절 재육성 루프의 동력이다.
- 중복은 희귀도와 무관하게 같은 값(1단계)이다. R 중복도 R 카드를, SSR 중복도 SSR 카드를 각각 돌파시킨다.
- 한계돌파 5단계의 OVR 효과(`economy_sim.py` 회귀 모델 추정): R OH 59.9 → **67.2**, SR OH 68.2 → **75.2**, SSR OH 77.6 → **82.6**. 즉 **풀돌 R ≈ 무돌 SR, 풀돌 SR ≈ 무돌 SSR** — training-mode 8.2 의 "한계돌파가 쌓이면 SR 도 A 에 닿는다"와 정합한다.

| 포지션 | R (장수) | SR (장수) | SSR (장수) | N 폴백 |
|---|---|---|---|---|
| S | — (0) | 68.8 → 74.7 (4) | 77.4 → 80.9 (2) | 53.5 |

### B.2.5 42명 풀의 "이미 가진 카드" 문제

시즌 3 까지 누적 스카우트 **52.4회에 중복 28.4회(54%)** (엔진 실측 n=200). 42장 풀에서 이는 구조적이다. 세 겹으로 대응한다.

| 대응 | 내용 | 효과 |
|---|---|---|
| ① 중복의 가치 보장 | 중복 = **한계돌파 1단계 즉시** (3시즌 누적 26.0단계) | 중복이 "꽝"이 아니라 **한계돌파 진척**이 된다 |
| ② 포지션 지정으로 풀 축소 | 지정 시 풀이 7~9장으로 줄어 원하는 자리를 채운다 | 초반 구멍 메우기 가속(B.4) |
| ③ 풀 확장 계획 | 런칭 42명 → **월 2~4명 신규**(GDD 9.6). 12개월 뒤 66~90명 | 중복률 하락 + 픽업 소재 공급 |

**풀 확장 시 확률 유지 규칙**: 신규 카드는 등급 정원에 더해지되 **등급별 총 확률(80/17/3)은 고정**하고 등급 내 개별 확률이 얇아진다. 즉 SSR 이 10 → 15명이 되면 특정 SSR 1명을 뽑을 확률은 0.30% → 0.20%. 이때 **픽업(정식)** 이 "원하는 1명"의 유일한 경로가 되므로, 픽업 없는 프로토타입 단계에서는 풀을 42명으로 고정한다.

### B.3.3 희귀도 획득과 첫 SSR

엔진 실측(n=200).

| 지표 | 값 |
|---|---|
| 첫 SSR 획득 누적 확률 | **시즌 1 52% · 시즌 2 72% · 시즌 3 84%** |
| 첫 SSR 까지 스카우트 횟수 | p10 **1** / p50 **7** / p90 **30** (3시즌 안에 얻은 167/200명 기준) |
| 시즌 1 SSR 기대 신규 획득 | 0.66장 · SR 2.8장 |
| 3시즌 누적 | 스카우트 52.4회 · 신규 R 14.9 / SR 7.3 / SSR 1.82 |

**목표(시즌 1 말~시즌 2 초)에 대한 판정: ✓.** v0.1 의 근사 추정(시즌 1 39%)보다 훨씬 이르다 —
**시즌 1 안에 52%, 시즌 2 까지 72%** 가 첫 SSR 을 받는다.

**왜 이렇게 빨라졌나 — 포지션 지정의 부수 효과.** p10 이 1 회인 것은 우연이 아니다.
엔진의 지정 스카우트는 **등급을 먼저 뽑고 그 등급에서 해당 포지션 카드를 고르는데, 그 포지션에 그 등급 카드가 없으면
같은 포지션의 아무 등급으로 폴백**한다. 세터 풀은 SR 4 + SSR 2 로 **R 이 한 장도 없어서**, 세터를 지정해 R 이 나오면
폴백이 SR/SSR 중 하나를 준다. 자동 플레이어는 첫 스카우트를 빈 자리(세터)에 쓰므로 **첫 뽑기가 사실상 SR+ 확정**이다.

> 이 폴백은 v0.1 B.4 ③ 이 적어 둔 "**N 무명 신인** 폴백"과 **다르다**. 엔진에는 N 무명 신인 카드가 없다(카드 풀은 `data/players.json` 42장뿐).
> 결과적으로 "구멍은 반드시 메워진다"는 목적은 달성하지만, "정식 카드를 대체하지는 않는다"는 단서는 성립하지 않는다 — 오히려 상위 카드가 나온다. 열린 이슈(D.2).

**SSR 하드 천장 60 은 여전히 사실상 장식이다.** 3시즌 누적 스카우트가 52.4회라 60회에 거의 닿지 않는다.
다만 첫 SSR 시점이 목표를 이미 만족하므로 **천장 60 을 유지한다**(v0.1 의 "60 → 40" 검토는 근거였던 39% 가 실측 52% 로 바뀌어 불필요해졌다).
`SSR 천장 40` 은 정식에서 미션 수입이 붙어 뽑기 횟수가 늘 때 다시 볼 문제로 남긴다(D.2).

| 상한 / 회복 | 120 / 6분당 1 (하루 240) |

### B.3.5 시나리오 비교 (근사 모델 — **상대 비교 전용**)

아래 표만은 `economy_sim.py`(n=500, seed 1) 출력이다. 엔진 검증 하네스는 대조군을 만들 수 없기 때문이다

`season-check.mjs --app` 으로 재보니 시즌 1 우승률 **96.5%**·스카우트 **84회**였다. 시작 티켓 +3장만으로도 우승률 22.5% 로 목표를 넘는다.
그래서 미션 보상을 **골드·조각으로 옮기고 시작 티켓을 엔진 기본 5장으로** 되돌렸다 — 측정 표는 B.6.7, 미션 표는 `web/engine/missions.js`.

## B.4 프로토타입에서 나온 문제에 대한 답

`prototype-play.md` 6.4절의 세 가지 문제를 새 설계가 어떻게 푸는지 대조한다.
**대조군("현행 프로토타입 규칙")은 엔진에 존재하지 않으므로 근사 모델 값이고, "신규 설계" 열은 엔진 실측이다.**
두 열의 출처가 다르니 절대 비교가 아니라 각 열 안의 추세로 읽어야 한다 — 열 제목에 출처를 적었다.

### ① 초반 티켓 고갈 (피드백 #6)

| 지표 | 현행 프로토타입 규칙 *(근사)* | **신규 설계 — 엔진 실측** |
|---|---|---|
| 시즌 1 스카우트 | 10.5회 | **13.0회** |
| 시즌 2 스카우트 | 6.0회 ← **감소** | **16.5회** |
| 시즌 3 스카우트 | 6.2회 | **22.9회** |

| 시즌 1 무승 비율 | 19% | **0.0%** |
| 3시즌 내 라인업 7슬롯 충원 실패 | 44% | **0%** |

현행 규칙의 치명적 결함은 **시즌 2 에 스카우트가 오히려 줄어드는 것**(10.5 → 6.0)이다. 초기 5장을 다 쓰고 나면 승리(+1)만 남는데 승률이 낮아 12경기에서 3장뿐이다.
신규 설계는 **패배해도 조각 2개**가 들어오고(12경기 = 24조각 = 티켓 2), 순위 보상이 최하위에도 3장을 주며, 육성 마일스톤이 성적과 무관하게 시즌 1 에 5장을 준다.
"첫 승리 전 육성 5~6회 보장" 요구는 **초기 티켓 5 + 프리시즌 2회**로 충족된다 — 엔진 실측 첫 승리까지 육성 **p50 7회 · p10 4회**, 첫 승리 매치데이 p50 5, **무승 0.0%**.

| 지표 | 현행 프로토타입 규칙 *(근사)* | **신규 설계 — 엔진 실측** |
|---|---|---|
| 3시즌 누적 SR 획득 | 3.7장 | **7.3장** |
| 3시즌 누적 SSR 획득 | 0.68장 | **1.82장** |
| 첫 SSR 까지 스카우트 p50 | 9회* | **7회** |
| 3시즌 내 첫 SSR | 48% | **84%** |
| 3시즌 누적 한계돌파 | 3.2단계 | **26.0단계** |
| 3시즌 뒤 라인업 OVR p50 | 68.4 | **75.5** |

(*현행의 p50 이 낮은 것은 3시즌 내에 SSR 을 얻은 48% 안에서만 계산했기 때문 — 나머지 52% 는 아예 못 얻는다.)

기여 분해: **천장(SR 10회)이 SR 공급을 2배로 늘렸고**, 이것이 라인업 OVR 의 주 동력이다.
SSR 은 여전히 희소하지만(3시즌 1.82장) 그것이 의도다 — SSR 은 "언젠가 오는 사건"이지 로스터의 기반이 아니다.
기반은 **SR + 한계돌파한 R** 이다.

한계돌파 누적이 3.2 → 26.0 으로 크게 뛴 것은 규칙 변경 때문이다: 중복이 조각을 거치지 않고 **곧바로 1단계**를 준다(B.2.4).
3시즌 중복 28.4회가 거의 그대로 26.0단계가 된다(카드당 상한 5단계에 걸린 몫이 차이).

프로토타입 관찰(시드 3 이 MB 4 / OH 2 로 뽑혀 S·OP·L 자리에 8회차까지 연습생)이 정확히 재현된다: 지정 없이 일반만 쓰면 **S(단 6장, 그중 R 0장)와 OP(단 6장)** 에 구멍이 남는다. S 는 R 등급 카드가 아예 없어(런칭 42명 구성상 S 는 SR 4 · SSR 2) 일반 뽑기로는 17+3=20% 확률의 SR/SSR 을 기다려야 한다.

**포지션 지정 스카우트가 이 구조적 구멍을 직접 겨냥한다.** 지정 시 S 풀은 6장(SR 4 + SSR 2)이라 **무조건 SR 이상이 나온다**
— 등급을 먼저 뽑고 R 이 나오면 그 포지션의 아무 등급으로 폴백하는데, 세터에는 R 이 없기 때문이다(B.3.3).
자동 플레이어가 첫 티켓을 세터에 쓰므로 "세터가 연습생이라 공격 조립이 무너진다"는 최악의 시작은 실측에서 발생하지 않는다
(시즌 1 개막 라인업 OVR **56.1**, 매치데이 7 에 연습생 슬롯 0.3).

> **v0.1 의 두 가지 단서는 v0.2 에서 성립하지 않는다.**
> ① **튜토리얼 SR 세터 확정 지급은 구현되지 않았다** — 엔진 `createGame` 은 카드 0장으로 시작한다.
> 위 개막 OVR 56.1 은 세터를 **뽑아서** 확보한 뒤의 값이다.
> ② **N 무명 신인 폴백도 없다** — 카드 풀에 N 카드가 없어, 폴백은 같은 포지션의 상위 등급으로 간다.
> 결과적으로 "구멍은 메워진다"는 목표는 초과 달성하지만 "정식 카드를 대체하지는 않는다"는 제동 장치는 없는 셈이다(D.2).

## B.6 골드 소비처 (v0.5 신설)

### B.6.1 문제와 제약

v0.3 이 "노화가 지정 스카우트 수요를 만들어 골드 축적을 멎게 했다"고 적었지만, **신인 세대(v0.4)가 들어오면서
그 결론이 뒤집혔다.** 카드 풀이 42 → 87장으로 늘어 로스터가 계속 채워지자 **지정 스카우트 수요가 후반에 오히려 줄었고**
(시즌 5 지정 16.2회 → 시즌 15 8.6회), 유입은 시즌당 14,000~15,000 골드로 그대로라 잔액이 다시 쌓였다.

| 시즌 | 4 | 8 | 12 | 15 |
|---|---|---|---|---|
| 골드 잔액 (v0.4) | 15,256 | 12,526 | 18,110 | **31,157** |

소비처가 **포지션 지정 스카우트 하나뿐**이라, 그 하나의 수요가 마르면 재화가 의미를 잃는다.

**제약이 설계를 거의 결정했다.**

1. **골드로 전력을 사면 안 된다.** A.4.4.1 의 성분 분해에서 전력 상승의 압도적 1위는 "카드를 더 모은다"(시즌 8 기준 9.78 OVR,
   나머지 네 성분 합의 4배)다. 골드 → 티켓 · 골드 → 캠프 효율 · 골드 → 부상 감소는 전부 그 축을 직접 민다.
   밀면 A.4.4 의 사다리 밴드(시즌 4~15 우승률 40~80%)를 다시 캘리브레이션해야 한다.
2. **초반(시즌 1~3)을 건드리면 안 된다.** 초기 골드 1,200 = 지정 스카우트 1회이고, A.4.1 의 7개 목표가 전부
   시즌 1~3 에 걸려 있다. 새 소비처가 초반 지갑을 조금이라도 갉으면 지정 스카우트가 줄고 목표가 깨진다.
3. **후반으로 갈수록 커져야 한다.** 잉여가 후반에만 있으므로(시즌 4~12 순증 0~1,800, 시즌 13~15 순증 3,800~4,700),
   일정한 세금은 중반 지갑을 비우고 후반 잉여는 못 잡는다.

그래서 채택한 소비처는 **정보 · 외형/명성 · 유지비** 세 가지이고, **경기·육성 판정에 들어가는 값은 하나도 없다.**
이 불변식은 `node web/parity.mjs` 9.4 가 기계로 검증한다 — 같은 시드에서 *시설 만렙 + 리포트 30장을 산 게임*과
*아무것도 안 산 게임*이 **스카우트 20회의 카드 id · 졸업 OVR · 경기 세트 스코어까지 완전히 같아야** 통과한다.

### B.6.2 채택안과 기각안

| 후보 | 판정 | 근거 |
|---|---|---|
| **① 구단 시설 투자** (분석실 / 홈구장 / 명예의 전당, 3종 × 5단계) | **채택** | 매니저 장르의 정통 소비처이고 영구 투자라 큰 금액을 흡수한다. **단, 효과는 전부 비전력으로 잘라 냈다** — 캠프 효율·부상 감소를 붙이면 제약 1 을 어긴다 |
| **② 스카우트 리포트** (카드당 1회, 잠재 OVR·적성·전성기를 미리 본다) | **채택** | 정보라 전력 영향이 0 이고, 신인 세대가 매 시즌 5장씩 들어오므로 소비가 끊기지 않는다. 분석실과 묶여 시설 투자에 실용적 이유를 준다 |
| **③ 구단 운영비** (시설 유지비 + 계약 42명 초과분) | **채택** | 유일한 **자동·구조적** 싱크. 사지 않는 플레이어의 지갑도 정리한다. 계약 인원에 비례하므로 신인 세대와 함께 후반에만 커진다(제약 3) |
| ④ 골드 → 티켓 환전 | **기각** | 티켓 = 카드 = 전력 상승의 1위 축(제약 1). 환율을 나쁘게 잡아도 "운 나쁜 구간 완화"라는 목적 자체가 **분산을 줄여 기대 전력을 올리는 것**이라 사다리를 민다. 천장(B.2.2)이 이미 분산의 꼬리를 자르고 있어 필요성도 낮다 |
| ⑤ 재육성 · 한계돌파 비용 | **기각** | 후반 가중이 아니다 — 같은 자동 플레이어 정책으로 재육성 횟수를 세어 보면 **시즌 2 에 이미 8.1회**로 사실상 최댓값이고 시즌 15 도 8.0회다(별도 계측 n=24). 시즌 2~3 에 회당 1,200골드를 물리면 지정 스카우트 예산을 그대로 잡아먹어 제약 2 를 어긴다 |

| ⑦ 재계약 · 컨디셔닝(하락 1시즌 지연) | **기각(유지)** | v0.3 E.4 에서 이미 "노화 수정을 골드로 되사는 장치"라 기각했다. 판단을 뒤집지 않았다 |

> **왜 시설 효과를 비전력으로 잘랐나.** 요구사항은 "전력 소비처를 넣으려면 효과를 측정해 사다리·보상으로 상쇄하라"였다.
> 상쇄는 가능하지만 사다리 g 재캘리브레이션 = A.4.1(7개) + A.4.4(20개) 목표를 전부 다시 맞추는 작업이고,
> **안전한 쪽만으로 목표가 달성됐으므로**(B.6.5) 굳이 위험을 지지 않았다. 전력형 시설(회복동·웨이트장)은
> D.2 의 열린 이슈로 남긴다.

### B.6.3 규칙과 가격표

**① 구단 시설** — 3종 × 5단계. 언제든 1단계씩 산다. 환불 없음.

| 시설 | 1 | 2 | 3 | 4 | 5 | 누적 | 효과(비전력) |
|---|---|---|---|---|---|---|---|
| **분석실** | 1,500 | 3,500 | 6,000 | 9,500 | 14,000 | 34,500 | 스카우트 리포트가 단계마다 **−180골드**, 5단계에서 **무료** |
| **홈구장** | 2,000 | 4,000 | 7,000 | 11,000 | 16,000 | 40,000 | 관중 규모·홈 경기 연출 등급 (외형) |
| **명예의 전당** | 1,500 | 3,500 | 6,500 | 10,000 | 15,000 | 36,500 | 은퇴 선수 헌액·통산 기록 전시 규모 (외형. E.4 "은퇴식" 제안의 자리) |

총 등급 합(0~15)이 **구단 명성**이다: 0 신생 / 1~3 지역 / 4~6 준수 / 7~9 명문 / 10~15 전통의 명문.
만렙 총투자 **111,000골드**.

**② 스카우트 리포트** — 카드 1장당 1회 결제, 이후 무제한 재열람. 정가 **900골드**(분석실 등급마다 −180 → 5단계 0).
내용은 전부 이미 카드 데이터에 있는 값이다: 잠재 OVR(한계돌파 반영값 포함) · 10스탯 잠재력과 남은 여유 ·
훈련 5종 적성(D~S) · 핵심 3스탯 · 현재 나이와 전성기 종료·은퇴 시즌 · 고유 스킬. 분석실 3단계 이상이면 심화 항목이 붙는다.
**RNG 를 한 번도 쓰지 않는다** — `seedIndex` 가 움직이지 않으므로 리포트를 사도 다음 스카우트 결과가 바뀌지 않는다(C.4).

**③ 구단 운영비** — 시즌 결산에서 보상을 받은 **직후** 자동 차감.

```
운영비 = 시설 등급 합 × 400  +  max(0, 계약 선수 − 42) × 200
계약 선수 = 보유 카드 중 은퇴하지 않은 것
미납 시   = 있는 만큼 내고(잔액 0) 가장 높은 등급의 시설을 1단계 강등한다(환불 없음)
```

무료 슬롯 **42** 는 런칭 카드 풀 = 리그 6구단 정원과 같은 숫자다. 신인 세대(docs/rookies.md)가 매 시즌 5장씩
풀을 늘리기 전에는 보유가 42장을 넘지 않으므로 **시즌 8 까지 실질 0원**이고, 그 뒤로 커진다 — 제약 3 을 만족하는 유일한 형태였다.
미납 강등은 "선수단이 너무 크면 방출(`releaseInstance`)해야 한다"는 압력을 만든다.

### B.6.4 언제 살 수 있는가 — 초반 잠금은 가격이 아니라 예비비가 만든다

가격표만으로는 초반을 지킬 수 없다. 시즌 1 말 잔액이 8,600 이라 1,500짜리 시설을 **살 수는 있기** 때문이다.
그래서 엔진은 **권장 예비비 `reserveGold = 13,200`**(= 지정 스카우트 11회분)을 상수로 두고,
UI 와 검증 하네스의 자동 플레이어가 이 값을 남기고 남는 골드만 쓴다.

```
소비 정책(web/season-check.mjs spendPhase — "잘하는 유저" 모델)
  시즌 결산 화면에서:
    ① gold − 다음 단계 가격 ≥ 13,200 인 동안, 가장 싼 시설부터 1단계씩 산다
    ② 그래도 남으면 아직 안 본 보유 카드의 스카우트 리포트를 산다
  → 예비비를 남기므로 **다음 시즌의 지정 스카우트를 굶기지 않는다.** 이것이 밸런스를 지키는 핵심이다.
```

시즌 1~3 잔액대(8.6k / 9.0k / 9.3k)는 `13,200 + 1,500 = 14,700` 에 한참 못 미친다 → **초반에는 소비처가 사실상 잠긴다.**
운 좋은 상위 표본만 시즌 1~3 에 1단계를 산다(실측 시즌 3 평균 투자 900골드 = 표본의 약 20%).
`parity.mjs` 9.2 가 "초기 골드 1,200 < 최저가 시설 1,500" 과 "예비비 > 시즌 1~3 잔액대"를 불변식으로 잡아 둔다.

### B.6.6 남은 격차

- **자동 플레이어가 시설을 사는 것은 정책 가정이다.** 시설·리포트는 전력을 안 주므로 "안 사고 모으기만 하는" 유저도 성립한다.
  그 경우 잔액을 잡는 것은 **운영비 하나**뿐이고, 시즌 15 기준 연 2,173골드라 잉여를 다 걷지는 못한다.
  외형·명성이 실제로 구매 동기가 되는지는 UI 가 붙어야 확인된다(E.5).
- **명성이 아무것도 안 한다.** 지금은 표시값이다. 리그 순위·관중·이적(정식)에 명성을 연결하면 동기가 생기지만,
  연결하는 순간 전력에 닿을 위험이 있어 이번 판에서는 끊어 두었다.
- **전력형 시설(회복동·웨이트장)을 넣을지.** 넣으면 사다리 재캘리브레이션이 필요하다(D.2).
- **리포트가 자동 플레이어의 의사결정을 바꾸지 않는다.** 하네스는 이미 카드 데이터를 다 보고 최적 정책을 쓰므로
  리포트의 실제 가치(= 정보가 없는 사람의 선택 개선)는 측정되지 않았다. 평균 유저 표본과 같은 미측정 항목이다.

- **티켓은 1장이 3%p다.** 시즌 1 에 티켓이 1장 늘 때마다 우승률이 3%p 안팎 오른다(5→8 장: 12→22.5%). 시작 티켓 +3 이 이미 목표 밖이라
  온보딩 보너스를 티켓으로 줄 여지는 없다. 이것이 B.3.5 "정식 미션은 티켓으로 주면 안 된다"의 실측 근거다.
- **골드도 공짜가 아니다.** 골드 5,300 은 포지션 지정 스카우트를 시즌 1~3 에 3회 늘려 첫 우승 시즌 2~3 누적을 56→49% 로 끌어내린다.
  절반(2,650)이면 기준선과 같은 여유로 통과한다.
- **조각 6** 은 첫 스카우트·첫 경기에서 3개씩 — 조각이 쌓여 티켓이 되는 것을 보여 주는 용도이고 티켓 0.5장 값이다.
- 채택안은 seed 7 · n=400 에서도 9/9 (S1 승률 45.7% · 순위 4.47 · 우승 17.0% · 첫 우승 S2~3 50.7% — 같은 seed 의 기준선은 52.0%). 장기 `--long --n 120 --app` 도 20건 전부 통과(시즌 4~15 우승률 48~70%).
- **부수 발견:** 앱의 "한 팀을 완성한다(연습생 0명)" 미션은 로스터의 연습생 수로 재고 있었는데 연습생 7명은 늘 로스터에 남으므로
  **영영 달성할 수 없었다.** 라인업 7자리 중 정식 카드 수로 고쳤다(하네스 달성률 0% → 100%). 상단 바의 조각 표시도 `/3` 으로 굳어 있던 것을 엔진 값(12)으로.

# C. 구현 인터페이스 초안

> **v0.2 주 — 실제로 구현된 곳은 여기가 아니다.** 리그·경제 계층은 브라우저 플레이용 자바스크립트
> **`web/engine/season.js`** (+ `web/engine/game.js` 의 재화·스카우트)에 먼저 구현됐고, 이 문서의 v0.2 수치는 전부 거기서 나왔다.
> 아래 C# 설계는 **아직 만들지 않은 `sim/VolleySim.League/` 의 계획**이다(현재 솔루션에는 Core·Training·Play·Cli 만 있다).
> 두 구현을 언젠가 맞출 때는 `web/PARITY.md` 가 대조표 역할을 한다. 타입 이름은 계획이고, 실제 API 목록은 `web/PARITY.md` 시즌 계층 절에 있다.

리그·경제 라이브러리는 **엔진 비의존 순수 C#**(netstandard2.1, 외부 의존 0)으로 만들어 Unity 클라이언트와 .NET 서버가 같은 어셈블리를 쓴다(GDD 11절). 배치: `sim/VolleySim.League/`(신규 프로젝트) — `VolleySim.Core` 를 참조하고 `VolleySim.Training` 은 참조하지 않는다(경기·재화 규칙만 담당, 육성은 호출자가 조립).

## C.4 결정성 (시드) 요구

`match-sim.md` 10절의 결정성 요구를 리그 계층으로 확장한다. **같은 `LeagueState` + 같은 입력 = 같은 결과**여야 서버 재검증과 리플레이가 성립한다.

| 대상 | 시드 파생 | 비고 |
|---|---|---|
| 시즌 일정 셔플 | `H(accountSeed, seasonNumber, "schedule")` | 시즌마다 대진 순서가 다르되 재현 가능 |
| 매치데이 경기 | `H(seasonSeed, matchDay, fixtureIndex)` | 경기 하나의 시드가 다른 경기와 독립 → 병렬 시뮬 가능 |
| 포스트시즌 경기 | `H(seasonSeed, "po", round, game)` | |
| 스카우트 1회 | `H(accountSeed, "scout", pullIndex)` | `pullIndex` 는 계정 통산 뽑기 횟수 — **재시도로 결과를 바꿀 수 없다** |
| 육성 세션 | 기존 `TrainingSession` 시드 규칙 유지 | `H(accountSeed, "train", runIndex)` |
| 연습생 세대 | `H(accountSeed, "filler", seasonNumber)` | |

- 해시 `H` 는 `DeterministicRandom` 의 SplitMix64 확장을 그대로 쓴다(정수 연산만, 플랫폼 무관).
- **난수 소비량을 결과에 기록**한다(`MatchResult.RandomDraws` 와 동일한 패턴) — 서버·클라 불일치 조기 발견용.
- 부동소수점 주의사항은 `match-sim.md` 10절 그대로. 리그 계층은 **정수·비교 연산만** 쓰도록 설계했다(승점·타이브레이크의 세트 득실률만 double 이며, 이는 비교에만 쓰이고 누적되지 않는다).

### E.4 기획으로 남긴 제안 (구현하지 않음)

- **은퇴식.** 통산 기록(경기 수·득점·타이틀)을 요약한 화면 + 영구 보존되는 "구단 레전드" 목록. 지금은 데이터만 있고 화면이 없다.
- **코치 보너스.** 은퇴 선수를 서포터로 쓰면 추가 효과(예: 같은 포지션 후배 육성 시 힌트 +1). 현재는 일반 서포터와 동일하게 취급한다 —
  넣는다면 A.4.4 의 밸런스를 다시 재야 한다.
- **재계약·컨디셔닝.** 골드로 하락을 1시즌 늦추는 유료 선택지. **의도적으로 넣지 않았다** — 이번 수정의 효과를 골드로 되사는 장치라
  넣으려면 가격과 상한을 A.4.4 밴드 안에서 다시 캘리브레이션해야 한다.
