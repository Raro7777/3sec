# A. 리그 시즌

## A.1 참가 구조와 시즌 포맷

### A.1.1 참가 구조

`world.md` 1.2절의 "블룸 프로젝트" 설정을 그대로 쓴다. 리그는 6개 기존 구단 + 리그가 창단 특례로 승인한 **신생 구단(플레이어)** = **7팀**이다.

| 항목 | 값 | 근거 |
|---|---|---|
| 참가 팀 | 7 (플레이어 1 + AI 6) | `data/teams.json` 6구단 + 플레이어 구단 |
| 정규 포맷 | 더블 라운드로빈 (홈 1 · 원정 1) | 팀당 12경기 |
| 매치데이 | **14** | 홀수 팀이라 라운드마다 1팀 휴식(bye). 각 팀 bye 2회 |
| 경기 형식 | 5세트 3선승, 25점(5세트 15점), 2점차 | `match-sim.md` 4.1 그대로 |
| 홈/원정 | 라운드로빈 배정으로 홈 6 · 원정 6 균등 | 홈 이점은 A.3.4 |

> `world.md` 1.1절은 "6구단 5라운드 25경기"로 적혀 있다. 플레이어 구단이 들어오면 7팀이 되고, 5라운드(팀당 30경기)는 외곽 루프 시간(A.2)을 3배로 늘린다. **이 문서가 리그 포맷의 기준이며 `world.md` 1.1절은 세계관 텍스트로 읽는다** — 정식 서비스에서 시즌 길이를 늘릴 때 3라운드(팀당 18경기)까지가 상한이다(열린 이슈 D.2).

### A.1.2 승점과 순위 결정

```
승점: 3-0 승 / 3-1 승 → 3점,  3-2 승 → 2점,  2-3 패 → 1점,  0-3·1-3 패 → 0점
```

7팀 × 12경기 = 42경기, 최대 승점 36. 순위 타이브레이크는 아래 순서로 적용한다(모두 결정적 — 동전던지기 없음).

| 순위 | 기준 | 비고 |
|---|---|---|
| 1 | 승점 | |
| 2 | 승수 | 3-2 승 2점 규칙 때문에 승점이 같아도 승수가 다를 수 있다 |
| 3 | 세트 득실률 (획득 세트 / 잃은 세트) | V리그 규정 |
| 4 | 점수 득실률 (총 득점 / 총 실점) | |
| 5 | 승자승 (해당 팀 간 상대 전적 승수) | |
| 6 | 팀 ID 사전순 | 최종 결정 규칙. 서버·클라이언트 동일 결과 보장 |

### A.1.3 포스트시즌 — 블룸 챔피언십

정규 상위 **4팀**. 정규 1위 우대를 두 겹으로 준다(정규 시즌을 의미 있게 만들고, 4번 시드의 요행 우승을 막는다).

| 라운드 | 대진 | 형식 | 홈 |
|---|---|---|---|
| 준PO | 3위 vs 4위 | **단판** | 3위 |
| PO | 2위 vs 준PO 승자 | **3전 2선승** | 2위가 1·3차전 |
| 챔프전 | 정규 1위 vs PO 승자 | **5전 3선승 + 정규 1위 1승 어드밴티지** | 1위가 1·3·5차전 |

- **프로토타입 축약안**: 준PO 단판 / PO 단판 / 챔프전 3전 2선승 + 어드밴티지 1승. 콘솔에서 시즌 1회 소요를 3경기 이하로 줄인다. 규칙 상수(`SemiBestOf` / `PoBestOf` / `FinalBestOf` / `FinalAdvantage`)만 다르고 코드는 같다.
- 어드밴티지 1승은 실제 V리그 규정에는 없지만(KOVO 챔프전은 5전 3선승), 7팀 12경기의 짧은 정규 시즌에서 **정규 1위가 플레이오프에서 뒤집히는 비율**을 통제하기 위한 게임적 장치다. 시뮬에서 이 규칙을 빼면 시즌 1 우승률이 13% → 22% 로 오른다(C.4 캘리브레이션 이력 4회차).

## A.2 시즌 캘린더와 외곽 루프

### A.2.1 매치데이 = 세션 1회

**매치데이 하나가 플레이 세션 하나**다. 이것이 리그와 육성을 묶는 단위다.

```
[매치데이 N 시작]
  → 스카우트(보유 티켓 소진, 0~2회)            ~1분
  → 한계돌파(조각 30 이상이면)                  ~30초
  → 육성 1회 (스태미나 30)                      ~10분 (스킵 2분 / 자동 3.6분)
  → 라인업·전술 점검                            ~1분
  → 매치데이 경기 (자동 1분 / 관전 5분)          1~5분
  → 결과·보상 → 순위표 갱신
[매치데이 N+1 …]
```

| 항목 | 값 | 근거 |
|---|---|---|
| 매치데이당 육성 | **1회 (기준선)** | 시간 예산과 사다리 밸런스(A.4)를 이 값에 맞췄다 |
| 프리시즌 캠프 | 시즌 1 개막 전 **2회**만 | 튜토리얼 + 첫 로스터 확보. 시즌 2 이후의 프리시즌은 매치데이 루프에 흡수 |
| 시즌 1 총 육성 | **16회** (2 + 14) | 시뮬 기준선 |
| 매치데이 소요 | 수동 **≈ 15분** / 스킵·자동 **≈ 5분** | 육성 9.2분(training-mode 1.2) + 경기·기타 |
| 한 시즌 소요 | 수동 **≈ 3.5~4시간** / 자동 **≈ 1.2시간** | 14 매치데이 |
| 한 시즌 실시간 | **1~2주** (하루 1~2 매치데이) | GDD 1절 "중기 루프 1~2주" |

### A.2.2 스태미나와의 정합 (열린 이슈)

`training-mode.md` 10절: 육성 1회 = **스태미나 30**, 상한 **120**, 회복 **6분당 1**(하루 240).

| 계산 | 값 |
|---|---|
| 하루 자연 회복 | 240 (+ 일일 미션 30, 정식) = **270** |
| 이론상 하루 육성 | 270 / 30 = **9회** |
| 상한 120 의 제약 | 한 번 접속에 최대 4회 연속. 9회를 다 쓰려면 하루 3회 이상 접속 |
| 무과금 일일 기대 (training-mode 10절) | **3~4회** |

**즉 스태미나는 매치데이당 육성 1회를 강제하지 않는다.** 하루에 매치데이 1개만 진행해도 스태미나가 남고, 열심히 하는 유저는 매치데이당 3~4회 육성할 수 있다. 이것이 이 설계의 가장 큰 미해결 지점이다.

| 대응안 | 내용 | 판정 |
|---|---|---|
| **(a) 매치데이 게이팅** | 매치데이를 넘겨야 다음 육성 슬롯이 열린다(육성 1회/매치데이 하드 캡) | 스태미나가 무의미해지고 "하고 싶은데 못 한다"의 불만. **기각** |
| **(b) 남는 스태미나를 다른 소비처로** | 재육성·평가전 반복·연습경기·소재 던전에 스태미나를 쓰게 하고, **리그 로스터에 반영되는 육성은 매치데이당 1회만 대표 갱신 가능** | 유력. 대표 인스턴스 갱신에 쿨다운을 두는 셈 |
| **(c) 그냥 둔다** | 헤비 유저가 빨리 강해지는 것을 허용. 사다리 g 를 유저 진척도에 연동 | 라이브 서비스에서는 흔한 해법이지만 g 를 진척도 연동하면 "사다리" 서사가 깨진다 |

시뮬에 매치데이당 육성 2회(라이트-헤비 중간) 시나리오를 넣어 영향을 측정했다: **시즌 1 우승률 13% → 31%, 4강 37% → 64%** (B.3.5 표). 사다리가 한 시즌 앞당겨진다. **(b) 를 1순위로 두되 프로토타입에서는 (c) 로 두고 실측한다**(D.1 검증 항목).

### A.2.3 시즌 경계

```
매치데이 14 종료
  → [정규 시즌 결산] 최종 순위표 · 개인 기록(득점/블로킹/서브/리시브 1위) · 내 팀 시즌 리포트
  → [포스트시즌] (4위 이내일 때만 플레이, 아니면 관전/스킵 가능 — 보상은 순위 보상만)
  → [시즌 결산 화면] A.5.2
  → [사다리 상승] g += 10~13%p, AI 구단 스탯 재계산, 연습생 7명 신규 세대로 교체
  → [프리시즌] 육성 1회 + 스카우트
  → 다음 시즌 매치데이 1
```

### A.2.4 라이브 서비스 시즌과의 대응

| 게임 내 | 라이브 운영 | 비고 |
|---|---|---|
| 블룸 리그 1시즌 (14 매치데이, 실시간 1~2주) | **시즌패스 1주기의 절반** | 패스는 2주 단위가 흔하다 |
| 시즌 사다리 g | **계정별로 진행**(서버 저장). 유저마다 시즌 번호가 다르다 | 랭킹은 g 가 아니라 "시즌 번호 + 승점"으로 매칭 |
| 시즌 랭킹 | 같은 시즌 번호끼리 승점·세트 득실 랭킹 | 사다리가 개인 진척도라 시즌 번호를 리그로 나눈다 |
| 픽업·이벤트 | **실시간 캘린더**(2~4주). 게임 내 시즌과 무관 | 픽업이 리그 시즌에 묶이면 운영이 경직된다 |

**핵심 결정: 게임 내 시즌은 개인 진척도, 라이브 시즌(패스·픽업·랭킹 기간)은 실시간 캘린더로 분리한다.** 두 개를 묶으면 늦게 시작한 유저가 시즌 1을 건너뛰어야 하거나, 빠른 유저가 기다려야 한다.

## A.3 AI 구단 규칙

### A.3.1 시즌 사다리 — 성장률 g

`prototype-play.md` 6.4 #1 의 관찰이 근거다. `players.json` 초기치 그대로면 연습생만으로도 6% 이기고 졸업생 6명이면 70~90% 이긴다. 잠재력 60% 성장이면 8회 육성해도 6~28%. **35% 가 첫 승리 2~4회차 · 8회차 승률 20~60% 의 사다리를 만들었다.**

```
실효 스탯(선수 p, 시즌 n) = round( clamp( stats_p + g(n) × (potential_p − stats_p), 0, 100 ) )
```

| 시즌 n | g(n) | 6구단 라인업 OVR 평균 | 최약(라온) | 최강(연화) | 전 시즌 대비 |
|---|---|---|---|---|---|
| 1 | **35%** | **65.3** | 62.9 | 67.0 | — |
| 2 | **48%** | 68.1 | 65.8 | 69.7 | +2.8 |
| 3 | **58%** | 70.2 | 68.1 | 71.8 | +2.1 |
| 4 | **66%** | 71.9 | 69.9 | 73.4 | +1.7 |
| 5 | **72%** | 73.2 | 71.2 | 74.7 | +1.3 |
| 6 | **76%** | 74.0 | 72.1 | 75.5 | +0.8 |
| 7+ | **80% (상한)** | 74.9 | 73.1 | 76.4 | +0.9 → 0 |

성장률의 **증가폭이 체감**한다(+13 → +10 → +8 → +6 → +4 → 상한). 이유는 A.4 에 있다: 플레이어 로스터의 성장도 체감하므로 사다리가 선형이면 시즌 5 이후 영원히 못 이기거나 영원히 지지 않는다.

**같은 선수, 두 얼굴.** `world.md` 1.2 의 "공개 스카우트 명단" 프레임을 규칙으로 굳힌다.

| 맥락 | 능력치 | 화면 표기 |
|---|---|---|
| 스카우트 대상(플레이어가 뽑는 카드) | `stats` = **신인 초기치** | "원소속: 연화 크레인즈 · 등록: 육성 명단" |
| 리그 상대(원소속 구단 소속으로 출전) | `stats + g × (potential − stats)` = **성장 버전** | 구단 로스터 화면에 실효 스탯 표시 |
| 내 팀에 편입된 뒤 | 육성 졸업 확정치(`PlayerInstance.FinalStats`) | 유니폼 레이어 교체(GDD 9.2) |

서사: **여섯 구단은 매 시즌 유망주를 공개 명단에 올려야 하지만, 명단에 올린 선수를 자기들도 계속 키운다.** 플레이어가 소이든을 스카우트하는 것은 "연화가 아직 꽃피우지 못한 원석"을 데려오는 것이고, 리그에서 마주치는 소이든은 "연화에서 g만큼 자란 소이든"이다. 같은 선수가 양쪽에 존재하는 것이 아니라, **스카우트되는 순간 원소속 구단의 로스터에서 빠진다**(A.3.5).

### A.3.2 AI 구단 라인업

| 항목 | 규칙 |
|---|---|
| 로스터 | `data/players.json` 의 해당 `teamId` **7명 고정**(S1 · OH2 · OP1 · MB2 · L1) |
| 라인업 | 표준 **5-1** 로테이션. `Lineup.Standard51(S, OH1, MB1, OP, OH2, MB2, L)` |

| 부상 | **프로토타입 제외.** AI 구단은 부상 없음 |
| 컨디션 | **프로토타입 제외**(`TeamCondition = 1.0`). 정식에서 시즌 서사용 이벤트("연화 에이스 감기몸살")로 도입 검토 |
| 호흡도(케미) | 세터-공격수 기본 50 고정. 정식에서 "명문일수록 높게"(연화 70 / 라온 40) 검토 |

### A.3.5 스카우트된 선수의 원소속 구단 처리

플레이어가 카드를 스카우트하면 그 선수는 **원소속 구단 로스터에서 빠진다.** 구단은 7명이므로 빈 자리가 생긴다.

| 규칙 | 내용 |
|---|---|
| 결원 보충 | 그 구단의 **동일 포지션 육성 선수**(제네릭 N 카드, `RandomPlayerGenerator` overall = 해당 구단 평균 − 8)로 자동 대체 |
| 표기 | 구단 로스터에 "(육성 선수)" 배지. 리그 순위표 옆 "이적 현황" 탭에서 확인 |
| 밸런스 영향 | 강한 카드를 뽑을수록 그 구단이 약해진다 = **뽑기 성공이 리그에서 두 번 보상된다** |
| 되돌림 | 방출해도 원소속으로 돌아가지 않는다(조각으로 환급) |

이 규칙은 서사(공개 스카우트 명단 → 실제로 데려간다)와 게임성(SSR 획득의 체감 배증)을 동시에 만든다. 다만 6구단 전력 편차를 키우므로 **시뮬에는 아직 미반영**이다(D.2 열린 이슈 — 현재 시뮬은 구단 로스터를 고정으로 두므로 여기 실린 순위·승률은 **보수적 추정**, 즉 실제로는 플레이어가 조금 더 유리하다).

### A.4.2 왜 사다리가 필요한가 — 수식

플레이어 라인업 OVR 을 `P(n)`, AI 구단 평균을 `C(n) = f(g(n))` 라 하자. 승률은 밸런스 리포트 9절(팀 overall 57/62/67/72/77 → 8.5/23.6/49.5/76.3/90.8%)을 로지스틱으로 회귀한 근사식이다.

```
승률(경기) ≈ sigmoid( 0.235 × (P − C) + 홈보정 )
```

`0.235` 는 **OVR 1 차이 ≈ 승률 5.8%p**(동급 근방)를 뜻한다. OVR 5 차이면 76%, 10 차이면 91%.

플레이어의 성장은 **로스터 7슬롯의 최댓값 갱신**이라 강하게 체감한다:

```
P(n) ≈ (1/7) Σ_slot  max( 그 포지션에서 보유한 인스턴스들의 OVR ,  연습생 46 )
```

시즌 1 초 4개 슬롯이 연습생(46)이므로 **첫 4~6회 육성은 슬롯당 +14~18 OVR** 을 준다(라인업 OVR 55.0 → 64.8). 그다음부터는 이미 R 카드(60)가 앉은 자리를 SR(69)로 바꾸는 **+9**, 다시 SSR(78)로 바꾸는 **+9** 뿐이고, 그마저 카드 운에 걸린다.

| 시즌 | 플레이어 ΔP | AI ΔC | 격차 변화 |
|---|---|---|---|
| 1 (개막→종료) | 55.0 → 67.5 = **+12.5** | 65.3 (고정) | −10.3 → **+2.2** |
| 1→2 | 67.5 → 71.0 = **+3.5** | 65.3 → 68.1 = +2.8 | +2.2 → **+2.9** |
| 2→3 | 71.0 → 73.5 = **+2.5** | 68.1 → 70.2 = +2.1 | +2.9 → **+3.3** |
| 3→4 | 73.5 → 75.0 = **+1.5** | 70.2 → 71.9 = +1.7 | +3.3 → **+3.1** |
| 4→5 | 75.0 → 76.1 = **+1.1** | 71.9 → 73.2 = +1.3 | +3.1 → **+2.9** |

**이것이 g 증가폭을 체감시킨 이유다.** 플레이어의 ΔP 가 +12.5 → +3.5 → +2.5 → +1.5 → +1.1 로 줄기 때문에, g 를 시즌당 +10%p 로 고정하면(ΔC ≈ +2.2 일정) 시즌 4 부터 격차가 계속 줄어 결국 플레이어가 다시 진다. 반대로 g 증가폭을 처음부터 작게 잡으면 시즌 2 에 이미 압도한다. **ΔC 를 ΔP 에 맞춰 체감시키면 격차가 +2.9~+3.3 (승률 62~64%) 에서 고원을 이룬다** — "우승은 하지만 매 시즌 싸워야 하는" 상태.

### A.4.3 사다리가 만드는 압박

시즌 4 이후 g 가 상한(80%)에 닿으면 AI 는 더 이상 강해지지 않는다. 그때부터는 **로스터를 안 키우면 순위가 유지된다**. 이것은 의도된 종착점이다 — 무한 사다리는 F2P 유저를 이탈시킨다. 이후의 도전 축은 리그가 아니라 **PvP 랭킹·픽업 카드·완성도 갱신**으로 넘긴다(GDD 6·8절).

### B.1.2 왜 골드를 새로 두는가

프로토타입에는 티켓과 조각뿐이라 **"돈이 있는데 쓸 데가 없다/티켓이 없어 아무것도 못 한다"의 두 상태만** 존재했다. 골드는 세 가지를 한다.

1. **포지션 지정 스카우트의 가격표.** 티켓 1 + 골드 1,200. 티켓만으로 지정할 수 있으면 일반 스카우트를 아무도 안 쓴다.
2. **경기의 즉시 보상.** 티켓은 12조각(경기 2~4회)을 모아야 나오지만 골드는 매 경기 들어온다 — 패배해도 손에 뭔가 남는다(프로토타입 피드백의 "패배 조각" 을 계승·확장).
3. **장비·굿즈(GDD 7절)의 화폐.** 정식에서 로스터 강화의 비가챠 축.

시뮬 결과 3시즌 뒤 골드 잔액 **10,614** — 소비처가 포지션 지정뿐이라 아직 남는다. 정식의 장비·보관함 확장이 이 잉여를 흡수해야 한다(D.2 열린 이슈).

## B.2 스카우트 상세

### B.2.1 종류별 비용·확률

| 종류 | 비용 | 풀 | 확률 | 천장 | 범위 |
|---|---|---|---|---|---|
| **일반 스카우트** | 티켓 1 | 상시 42명 전체 | R 80 / SR 17 / SSR 3% | SR+ 10 / SSR 60 (공유) | 프로토타입 |
| **포지션 지정 스카우트** | 티켓 1 + **골드 1,200** | 지정 포지션(S/OH/OP/MB/L)만 | 동일 (R 80 / SR 17 / SSR 3%) | **동일 카운터 공유** | 프로토타입 |
| **픽업 스카우트** | 젬 150 또는 픽업 티켓 1 | 상시 + 픽업 캐릭터 | 동일 + SSR 중 픽업 50% | **별도 카운터** SR+ 10 / SSR 60, 60회 천장 시 픽업 확정 | 정식 |
| 10연 (모든 종류) | 단가 × 10 | — | 동일 | **SR 이상 1장 보장**(10연 내 SR+ 가 없으면 10번째를 SR 로) | 프로토타입 |

**확률을 R 80 / SR 17 / SSR 3% 에서 바꾸지 않는 이유.** `prototype-play.md` 6.4 #2 는 "R 80% 가 로스터 성장을 R 카드에 묶는다(3시드 24회에서 SSR 0장, 첫 SSR 기대 33회)"고 지적했다. 확률을 올리는 대신 **천장 + 포지션 지정 + 조각 가치**로 풀었다. 이유:

- 확률 자체를 올리면(예: SSR 5%) 표기 확률이 경쟁작 대비 높아 보이지만 **분산은 그대로**라 "60회 뽑았는데 없다"는 유저는 여전히 생긴다. 천장은 분산의 꼬리를 자른다.
- R 카드가 무가치한 것이 근본 문제였는데, 이는 **조각 10개**(중복 R 도 한계돌파 재료)와 **포지션 지정으로 R 을 원하는 자리에 배치**하는 것으로 해소된다(B.4).
- 국내 확률형 아이템 표시 의무상 확률과 천장은 모두 공개해야 하므로, "천장 있는 3%" 가 "천장 없는 5%" 보다 설명하기 쉽고 유저 신뢰도 높다.

### B.2.2 천장 규칙

```
매 뽑기마다:
  pitySR  += 1
  pitySSR += 1
  if pitySSR >= 60:  결과 = SSR           # 하드 천장
  elif pitySR >= 10: 결과 = SR 또는 SSR    # SSR 비중 = 3/(3+17) = 15%
  else:              결과 = 기본 확률표
  결과가 SR 이상이면 pitySR = 0
  결과가 SSR      이면 pitySSR = 0
```

| 규칙 | 실효 등급 확률 | SSR 간격 평균 | SSR 간격 p50 / p90 / 최대 | SR+ 간격 p90 / 최대 |
|---|---|---|---|---|
| 천장 없음 | R 79.9 / SR 17.1 / SSR 3.09% | 32.4 | 23 / 73 / **260** | 11 / 45 |
| SR 10 만 | R 77.5 / SR 19.1 / SSR 3.43% | 29.1 | 21 / 65 / **236** | 10 / 10 |
| **SR 10 + SSR 60 (채택)** | **R 77.2 / SR 18.9 / SSR 3.87%** | **25.9** | 21 / 60 / **60** | 10 / 10 |
| SR 10 + SSR 50 (대안) | R 77.1 / SR 18.8 / SSR 4.10% | 24.4 | 21 / 50 / 50 | 10 / 10 |

(120,000회 뽑기, `economy_sim.py --only new`)

**천장 카운터는 일반과 포지션 지정이 공유한다.** 이유: 분리하면 "천장 직전에는 포지션 지정을 쓰면 손해"라는 역-최적화가 생겨 유저가 원하는 포지션을 못 뽑게 된다. 픽업만 별도 카운터를 두는 것은 업계 표준이고, 픽업 종료 시 카운터 이월 여부는 정식 정책으로 미룬다(D.2).

### B.2.4 중복 처리와 한계돌파

```
중복 카드 획득 → 해당 희귀도 조각 10개
조각 30개  → 한계돌파 1단계 (그 카드의 전 스탯 potential +3, 최대 5단계 = +15)
조각 12개  → 스카우트 티켓 1
조각 5개   → 상위 희귀도 조각 1 (R→SR→SSR, 대상 카드가 없을 때의 배출구)
```

- **한계돌파는 카드 단위**(인스턴스가 아님). 돌파 후에는 **재육성해야 반영된다** — "상한이 올랐으니 다시 키운다"가 `training-mode.md` 8.6절 재육성 루프의 동력이다.
- 조각이 희귀도별로 나뉘므로 R 중복은 R 카드만, SSR 중복은 SSR 카드만 돌파한다. SSR 조각이 남으면 티켓으로 바꿀 수 있어 완전 사장되지 않는다.
- 한계돌파 5단계의 OVR 효과(시뮬 추정): R OH 59.9 → **67.2**, SR OH 68.2 → **75.2**, SSR OH 77.6 → **82.6**. 즉 **풀돌 R ≈ 무돌 SR, 풀돌 SR ≈ 무돌 SSR** — training-mode 8.2 의 "한계돌파가 쌓이면 SR 도 A 에 닿는다"와 정합한다.

| 포지션 | R (장수) | SR (장수) | SSR (장수) | N 폴백 |
|---|---|---|---|---|
| S | — (0) | 68.8 → 74.7 (4) | 77.4 → 80.9 (2) | 53.5 |
| OH | 59.9 → 67.2 (7) | 68.2 → 75.2 (2) | 77.6 → 82.6 (3) | 51.0 |
| OP | 63.4 → 70.5 (1) | 70.7 → 77.2 (3) | 80.4 → 83.3 (2) | 53.8 |

| L | 64.5 → 72.1 (4) | 74.1 → 79.6 (1) | **83.8** → 84.9 (1) | 61.9 |

(기대 졸업 OVR, 최적 정책·서포터 없음. 한계돌파 0 → 5. `L SSR` = 백윤슬 단 1명이며 리베로 OVR 가중이 약점 스탯을 0 으로 두기 때문에 값이 높다 — `training-mode.md` 12.1 의 제네릭 SSR L 79.1 과의 차이는 카드 개성이지 모델 오차가 아니다.)

### B.2.5 42명 풀의 "이미 가진 카드" 문제

시즌 3 까지 누적 스카우트 46회에 **중복 23.9회(52%)**. 42장 풀에서 이는 구조적이다. 세 겹으로 대응한다.

| 대응 | 내용 | 효과 |
|---|---|---|
| ① 조각 가치 보장 | 중복 = 조각 10 = 한계돌파 1/3단계 + 티켓 0.83장 상당 | 중복이 "꽝"이 아니라 **한계돌파 진척**이 된다 |
| ② 포지션 지정으로 풀 축소 | 지정 시 풀이 7~9장으로 줄어 원하는 자리를 채운다 | 초반 구멍 메우기 가속(B.4) |
| ③ 풀 확장 계획 | 런칭 42명 → **월 2~4명 신규**(GDD 9.6). 12개월 뒤 66~90명 | 중복률 하락 + 픽업 소재 공급 |

**풀 확장 시 확률 유지 규칙**: 신규 카드는 등급 정원에 더해지되 **등급별 총 확률(80/17/3)은 고정**하고 등급 내 개별 확률이 얇아진다. 즉 SSR 이 10 → 15명이 되면 특정 SSR 1명을 뽑을 확률은 0.30% → 0.20%. 이때 **픽업(정식)** 이 "원하는 1명"의 유일한 경로가 되므로, 픽업 없는 프로토타입 단계에서는 풀을 42명으로 고정한다.

### ① 초반 티켓 고갈 (피드백 #6)

| 지표 | 현행 프로토타입 (초기 5 · 승리 +1 · 패배 조각 1/3) | **신규 설계** |
|---|---|---|
| 시즌 1 스카우트 | 11.2회 | **13.0회** |
| 시즌 2 스카우트 | 7.1회 ← **감소** | **14.1회** |
| 시즌 3 스카우트 | 7.7회 | **19.4회** |

현행 규칙의 치명적 결함은 **시즌 2 에 스카우트가 오히려 줄어드는 것**(11.2 → 7.1)이다. 초기 5장을 다 쓰고 나면 승리(+1)만 남는데 승률이 26%라 12경기에서 3장뿐이다. 신규 설계는 **패배해도 조각 2개**가 들어오고(12경기 = 24조각 = 티켓 2), 순위 보상이 최하위에도 3장을 주며, 육성 마일스톤이 성적과 무관하게 4장을 준다. "첫 승리 전 육성 5~6회 보장" 요구는 **초기 티켓 5 + 프리시즌 2회 + 첫 승리 시점 매치데이 4** 로 충족된다(첫 승리까지 육성 p50 6회, p10 4회).

### ② R 80% 로 인한 로스터 정체 (피드백 #2)

| 지표 | 현행 프로토타입 | **신규 설계** |
|---|---|---|
| 3시즌 누적 SR 획득 | 3.9장 | **8.7장** |
| 3시즌 누적 SSR 획득 | 0.65장 | **1.5장** |

(*현행의 p50 이 낮은 것은 3시즌 내에 SSR 을 얻은 53% 안에서만 계산했기 때문 — 나머지 47% 는 아예 못 얻는다.)

기여 분해: **천장(SR 10회)이 SR 공급을 2.2배로 늘렸고**, 이것이 라인업 OVR 의 주 동력이다. SSR 은 여전히 희소하지만(3시즌 1.5장) 그것이 의도다 — SSR 은 "언젠가 오는 사건"이지 로스터의 기반이 아니다. 기반은 **SR + 한계돌파한 R**(풀돌 R OH 67.2 ≈ 무돌 SR 68.2)이다.

### ③ 포지션 편중 (피드백 #3)

| 지표 | 현행(일반만) | 신규 − 지정 미사용 | **신규(지정 사용)** |
|---|---|---|---|
| 라인업 7슬롯 전원 정식 카드 도달 (누적 매치데이 p50 / p90) | **21 / 35** | 14 / 28 | **7 / 14** |
| 3시즌 내 미도달 | **38%** | 4% | **0%** |
| 시즌 1 중반(매치데이 7) 연습생 슬롯 | 1.9 | 1.1 | **0.4** |
| 3시즌 뒤 잔여 구멍 포지션 | S 0.28 · OP 0.15 · MB 0.01 | OP 0.03 | **전부 0.00** |
| 시즌 1 승률 | 25% | 36% | **43%** |

프로토타입 관찰(시드 3 이 MB 4 / OH 2 로 뽑혀 S·OP·L 자리에 8회차까지 연습생)이 정확히 재현된다: 지정 없이 일반만 쓰면 **S(단 6장, 그중 R 0장)와 OP(단 6장)** 에 구멍이 남는다. S 는 R 등급 카드가 아예 없어(런칭 42명 구성상 S 는 SR 4 · SSR 2) 일반 뽑기로는 17+3=20% 확률의 SR/SSR 을 기다려야 한다.

**포지션 지정 스카우트가 이 구조적 구멍을 직접 겨냥한다.** 지정 시 S 풀은 6장(SR 4 + SSR 2)이라 무조건 SR 이상이 나온다. 여기에 **튜토리얼 SR 세터 확정 지급**을 더해 "세터가 연습생이라 공격 조립이 무너진다"는 최악의 시작을 원천 차단했다(시뮬의 시즌 1 개막 라인업 OVR 55.0 은 세터가 이미 SR 인 상태의 값이다).

보조 장치: **지정 스카우트로 그 포지션에 정식 카드가 하나도 없으면 결과가 N 무명 신인**(포지션 프로파일 기반, 기대 졸업 OVR 51~62)으로 폴백한다. 연습생(46)보다 확실히 낫고 R(60~65)보다 낮아, "구멍은 반드시 메워지되 정식 카드를 대체하지는 않는다".

## C.4 결정성 (시드) 요구

`match-sim.md` 10절의 결정성 요구를 리그 계층으로 확장한다. **같은 `LeagueState` + 같은 입력 = 같은 결과**여야 서버 재검증과 리플레이가 성립한다.

| 대상 | 시드 파생 | 비고 |
|---|---|---|
| 시즌 일정 셔플 | `H(accountSeed, seasonNumber, "schedule")` | 시즌마다 대진 순서가 다르되 재현 가능 |
| 매치데이 경기 | `H(seasonSeed, matchDay, fixtureIndex)` | 경기 하나의 시드가 다른 경기와 독립 → 병렬 시뮬 가능 |
| 포스트시즌 경기 | `H(seasonSeed, "po", round, game)` | |
| 스카우트 1회 | `H(accountSeed, "scout", pullIndex)` | `pullIndex` 는 계정 통산 뽑기 횟수 — **재시도로 결과를 바꿀 수 없다** |
| 육성 세션 | 기존 `TrainingSession` 시드 규칙 유지 | `H(accountSeed, "train", runIndex)` |
| 연습생 세대 | `H(accountSeed, "filler", seasonNumber)` | |

- 해시 `H` 는 `DeterministicRandom` 의 SplitMix64 확장을 그대로 쓴다(정수 연산만, 플랫폼 무관).
- **난수 소비량을 결과에 기록**한다(`MatchResult.RandomDraws` 와 동일한 패턴) — 서버·클라 불일치 조기 발견용.
- 부동소수점 주의사항은 `match-sim.md` 10절 그대로. 리그 계층은 **정수·비교 연산만** 쓰도록 설계했다(승점·타이브레이크의 세트 득실률만 double 이며, 이는 비교에만 쓰이고 누적되지 않는다).

# D. 검증 가설과 열린 이슈

## D.1 구현 단계에서 실제 시뮬로 확인할 항목

이 문서의 리그·경제 수치는 **승률 로지스틱 근사**(`sigmoid(0.235 × ΔOVR)`) 위에서 나왔다. 실제 `MatchSimulator` 는 포지션별 기여가 비대칭이고(밸런스 리포트 v0.2-2: OH 1인 +12.6%p vs MB 1인 +11.1%p), 전술·컨디션·클러치가 얹힌다. **아래는 전부 실제 시뮬로 재측정해야 한다.**

| # | 가설 | 측정 방법 | 목표 | 근사 시뮬 결과 |
|---|---|---|---|---|
| E1 | 시즌 1 은 중위권 | `--auto-season 1` × 200 시드, 최종 순위 분포 | 평균 4~5위, 우승 ≤ 15% | 4.9위 / 13% |
| E2 | 첫 우승은 시즌 2~3 | 시즌 1~5 자동 플레이 × 200 시드 | S2+S3 누적 ≥ 45% | 50% |
| E3 | 사다리가 고원을 만든다 | 시즌 4·5 우승률 | 단조 증가 아님, 45~60% | 50% → 46% |
| E4 | 첫 SSR 시점 | 스카우트 로그 | 시즌 2 내 60% 이상 | 57% |
| E5 | 포지션 구멍이 시즌 1 에 메워진다 | 매치데이별 연습생 슬롯 수 | p90 ≤ 14 매치데이 | 14 |
| E6 | 티켓이 마르지 않는다 | 매치데이별 티켓 잔액 최솟값 | 시즌당 스카우트 ≥ 10회 | 13.0 / 14.1 / 19.4 |
| E7 | 육성 정책이 리그에 번역된다 | 안전 vs 최적 정책 자동 플레이 비교 | 우승률 차 ≥ 2배 | 3% vs 13% (S1) |
| E8 | 구단 아이덴티티가 로그에 보인다 | 구단별 공격 유형 비중·에이스율·블로킹 득점 | 태령 블로킹 1위, 적동 에이스 1위, 라온 속공 비중 1위 | 미측정 |
| E9 | 승점 규칙이 순위를 흔든다 | 3-2 승 2점 vs 3점 규칙의 최종 순위 차이 | 시즌당 1회 이상 순위 역전 | 미측정 |
| E10 | 타이브레이크가 결정적이다 | 같은 시드 재실행 시 순위표 완전 일치 | 100% | 설계상 보장 |
| E11 | 스카우트된 선수의 구단 결원 효과 | A.3.5 구현 후 6구단 전력 분산 | 최강-최약 격차 ≤ 6 OVR | **미반영**(현 추정은 보수적) |
| E12 | 스태미나가 실제 제약인가 | 실플레이 매치데이당 육성 횟수 로그 | 평균 1.0~1.5회면 기준선 유효 | 미측정 (A.2.2) |

## D.2 열린 이슈 체크리스트

**리그**

- [ ] **시즌 길이.** 12경기(14 매치데이)가 "리그 한 시즌"의 무게를 갖는가, 아니면 18경기(3라운드)가 필요한가. 후자는 시즌 소요 5.5시간·실시간 2~3주가 된다. 실플레이 체감으로 결정.
- [ ] `world.md` 1.1절(6구단 5라운드 25경기)과 이 문서(7팀 2라운드 12경기)의 텍스트 정합. 세계관 문서를 고칠지, 신생 구단 합류로 포맷이 바뀌었다는 설정을 넣을지.
- [ ] **챔프전 1승 어드밴티지.** 실제 V리그에 없는 규칙이라 배구 팬에게 어색할 수 있다. 대안: 정규 1위가 챔프전 홈 3경기(1·3·5차전) + 준PO 를 없애고 3팀 포스트시즌.
- [ ] **승강제.** 7팀 고정이라 "강등 위험"이 없다. 2부 리그를 넣을지, 아니면 시즌 사다리가 그 역할을 하는지.
- [ ] **A.3.5 미구현.** 스카우트된 선수의 원소속 구단 결원 처리는 설계만 있고 시뮬·코드에 없다. 구현 시 6구단 전력 분산이 커져 사다리 재캘리브레이션이 필요할 수 있다.
- [ ] **AI 컨디션·부상.** 프로토타입 제외로 결정했지만, 시즌 서사("연화 에이스 부상으로 시즌 아웃")의 가치가 크다면 되살릴지.
- [ ] **구단 전술의 실효성.** A.3.3 표가 승률을 흔들지 않고 로그 질감만 바꾸는지(E8). 흔든다면 구단 티어가 아이덴티티와 얽혀 사다리가 왜곡된다.
- [ ] **케미스트리 ×0.9 감쇠.** `training-mode.md` 8.6 의 "케미는 인스턴스 귀속"과 리그 라인업 교체의 긴장이 실제로 재미인지, 마찰인지.

**경제**

- [ ] **SSR 천장 60 vs 40.** 프로토타입 범위에서 60은 3시즌(46회)에 도달하지 않아 장식이다. A/B 로 결정(B.3.3).
- [ ] **정식 일일·주간 미션이 사다리를 깬다.** 티켓 1/일 + 3/주 를 얹으면 시즌 2 우승률 41% → 78%. 미션 보상을 골드·조각·스태미나로 바꾸거나 g 사다리를 재조정해야 한다(B.3.5) — **정식 설계 전에 반드시 결론.**
- [ ] **골드 잉여.** 3시즌 뒤 10,614 골드가 남는다. 장비·굿즈(GDD 7절)·보관함 확장·연습생 리롤의 가격표가 정해져야 소프트 재화가 의미를 갖는다.
- [ ] **스태미나가 제약이 아니다**(A.2.2, B.3.4). 대응안 (b)"대표 인스턴스 갱신 쿨다운" 이 유력하나 UX 마찰을 확인해야 한다.
- [ ] **매치데이당 육성 횟수.** 기준선 1회는 밸런스에서 역산한 값이지 유저 행동 관측값이 아니다. 실제가 2~3회면 사다리 g 를 35 → 55 → 70% 로 가파르게 재조정해야 한다.
- [ ] **10연 스카우트.** SR+ 1장 보장을 넣었지만, 프로토타입 경제에서 시즌당 티켓이 13~19장이라 10연을 모으는 것 자체가 부담이다. 프로토타입에서는 단차 뽑기만 노출할지.
- [ ] **조각 상향 변환 5:1** 의 비율. 너무 후하면 R 중복이 SSR 돌파로 흘러 희귀도 위계가 무너진다.
- [ ] **한계돌파 potential +3 의 육성 도달률 영향**(`training-mode.md` 13절 미해결). 잔여 잠재력이 늘면 강도 곡선 아래서 핫존 이득이 커져 실제 OVR 상승이 이 문서의 추정(+7.3 for LB5)보다 클 수 있다.
- [ ] **픽업 카운터 이월.** 픽업 종료 시 별도 카운터를 다음 픽업으로 넘길지, 소멸시킬지.
- [ ] **확률형 아이템 표시 의무의 정확한 적용 범위**(개별 카드 확률 표기 수준, 천장 표기 문구, 홈페이지 게시 요건) — 출시 전 법률 검토 필요. B.2.3 은 보수적으로 "전부 공개"를 전제했다.

**시뮬레이터 자체**

- [ ] `economy_sim.py` 의 승률 모델은 라인업 OVR 평균의 로지스틱이라 **포지션 비대칭·전술·클러치·호흡도를 무시**한다. 실제 `MatchSimulator` 로 교체한 검증이 D.1 의 전제다.
