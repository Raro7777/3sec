# 아트 파이프라인 (art-pipeline v0.1)

> 상태: **그림 제작 전 준비 완료.** 프롬프트 팩·슬롯인·규격 검사·회귀 테스트가 있고, 실제 이미지는 아직 0장이다.
> 이 문서는 "그림 한 장을 어떻게 게임 안까지 넣는가"의 절차서다.
> 스타일·규격의 근거는 [art-style-guide.md](art-style-guide.md)에 있고, 여기서는 **손이 움직이는 순서**만 적는다.
>
> 코드: `tools/art-prompts.mjs`(프롬프트 생성) · `web/art-pack.mjs`(수집·규격 검사) · `web/build.mjs`(인라인) ·
> `web/art-test.mjs`(회귀). 산출물: `art/00_guide/prompts/`.

## 0. 한 장 요약

```
① node tools/art-prompts.mjs          → art/00_guide/prompts/p001.txt  (그대로 복사해 붙이는 프롬프트)
② 이미지 생성 도구에서 생성 → 8장 중 1장 선택
③ 리터치(누끼·번호·QA)                → art-style-guide 8절
④ art/04_export/p001/p001_card.webp + p001_thumb.webp 로 저장
⑤ node web/art-pack.mjs               → 규격 확인
⑥ node web/build.mjs                  → 카드가 게임 화면에 뜬다
```

**④번 폴더에 파일을 넣는 것 말고는 코드를 건드릴 일이 없다.** 아트가 없는 카드는 지금처럼 SVG 플레이스홀더가 그려지고,
한 명씩 들어와도 레이아웃이 흔들리지 않는다(같은 상자·같은 비율).

## 1. 프롬프트 팩 (`tools/art-prompts.mjs`)

`docs/art-style-guide.md` 6절의 템플릿은 `{hairStyle}` 같은 빈 슬롯이 뚫려 있고, `data/players.json` 의 외형 값은
`"롱 하이 포니테일"`·`"플래티넘 블론드"` 같은 한국어다. 이 둘을 잇는 것이 이 스크립트다.

```bash
node tools/art-prompts.mjs           # 42명분 생성 + 커버리지 리포트
node tools/art-prompts.mjs --check   # 파일을 쓰지 않고 검사만 (CI 게이트)
node tools/art-prompts.mjs --id p001 # 한 명만 표준출력으로
```

한 명당 나오는 것: **카드(태그형 + 자연어형) · 스탠딩 · SD 토큰 · 표정 4종 · 네거티브 2종**(카드/스탠딩 공용, 토큰 전용).
공용 고정 파라미터는 `_params.txt`, 전체 목록은 `_index.md`.

### 1.0 태그형과 자연어형

같은 매핑표에서 **두 가지 형태**를 뽑는다. 어휘를 두 벌 관리하지 않으려고 자연어는 태그에서 기계적으로 만든다.

| 형태 | 대상 | 예 |
|---|---|---|
| 태그형 | 로컬 SD · 애니메 SDXL(Danbooru 태그 학습) | `high ponytail, long hair, platinum blonde hair, purple eyes, tareme` |
| 자연어형 | Higgsfield(Soul·Seedream·Flux) · Midjourney 등 호스팅 모델 | `A tall, slim and athletic young woman with fair skin, long platinum blonde hair worn in a high ponytail and gentle, softly drooping purple eyes.` |

변환 규칙에서 주의한 것: 질감(straight/wavy/curly/layered)은 `with wavy hair` 가 아니라 **형용사로 앞에** 붙이고,
자른 머리(bob/pixie/hime/cropped)에는 길이 수식을 붙이지 않으며(`in a cropped hair` 방지),
눈 색과 눈매는 **한 덩어리**로 만든다(둘 다 `eyes` 로 끝나면 문장이 깨진다).
체형은 태그(`tall, slim athletic build`)가 명사구라 문장용 형용사구를 따로 둔다(`tall, slim and athletic`).
42종 헤어 전부 출력해 눈으로 확인했다.

### 1.1 어휘는 닫혀 있다

| 항목 | 값 개수 | 매핑 |
|---|---|---|
| 헤어스타일 | 42 | 42 ✅ |
| 헤어 컬러 | 24 | 24 ✅ |
| 눈 색 | 20 | 20 ✅ |
| 체형 | 15 | 15 ✅ |

런칭 42명과 **신인 세대 생성기**(`web/engine/rookies.js`)가 같은 목록에서 값을 뽑기 때문에,
이 표가 가득 차 있으면 앞으로 생길 카드도 전부 프롬프트를 만들 수 있다.
매핑에 없는 값이 하나라도 들어오면 스크립트가 **에러로 죽는다** — 조용히 빈 슬롯으로 넘어가지 않는다.

### 1.2 데이터에 없어 생성기가 배정하는 값

`art-style-guide` 는 요구하는데 `data/players.json` 에는 필드가 없는 것이 둘 있다. 생성기가 **결정적으로** 배정하고,
그 사실을 각 프롬프트 파일 머리말에 적는다.

| 값 | 규칙 | 실측 |
|---|---|---|
| 피부 3톤(2.7) | id 정렬 순서로 주기 배정 후, 단일 톤 구단이 없게 보정 | A/B/C = 26/12/4 (62/29/10%, 권장 60/30/10) · 구단별 최소 2톤 |
| 눈매(2.5·6.2) | id 순서 + 포지션으로 tsurime/neutral/tareme 순환 | — |

정식으로 하려면 `data/players.json` 스키마에 `skinTone`·`eyeShape` 를 넣고 생성기는 그것을 읽게 바꾸면 된다(11절).

### 1.3 프롬프트 조립 규칙

- **체형은 데이터의 `bodyType` 이 담당하고, 포지션은 그 포지션에서만 나오는 특징만 얹는다**(S `long fingers`,
  OP `long legs, broad shoulders`, MB `long arms`). 그러지 않으면 `장신 슬림 애슬레틱` + `athletic build` 처럼 같은 말이 겹쳐
  태그가 흐려진다.
- 태그 나열은 중복 제거를 거친다.
- **토큰(6.7)은 공용 네거티브를 쓰면 안 된다** — 공용 쪽에 `chibi` 가 들어 있어 서로 싸운다. 전용 네거티브를 따로 낸다.
- 리베로는 구단 대비색 유니폼으로 조립한다(5.4). 카드만 봐도 리베로여야 한다.
- **작가명·작품명·스튜디오명을 넣지 않는다.**

## 2. 파일을 넣는 곳 (`art/04_export/`)

```
art/04_export/{pid}/
  {pid}_card.webp      3:4   (권장 2048×2732)   카드 일러스트
  {pid}_thumb.webp     1:1   (권장 512×512)     원형 초상 — 로스터·라인업·육성 목록
  {pid}_meta.json                                얼굴 좌표 등. 없어도 동작한다
```

- `webp` 가 `png` 보다 우선한다(같은 화질에 30~40% 크기). `png`·`jpg` 도 읽는다.
- **비율만 검사하고 해상도는 강제하지 않는다.** 작업 중에 낮은 해상도로 먼저 확인하는 편이 낫기 때문이다.
- 폴더 이름과 파일 접두사는 `data/players.json` 의 `id` 와 같아야 한다(`p001`…). 신인 세대 카드는
  런타임 생성이라 아트를 붙일 수 없다 — 항상 SVG 플레이스홀더다(11절 열린 이슈).

원본(`02_gen`)·작업 파일(`03_work`)·LoRA 데이터셋(`06_lora`)은 용량이 커서 저장소에 넣지 않는다.
**`04_export` 만 커밋한다**(art-style-guide 4.9).

```bash
node web/art-pack.mjs        # 지금 무엇이 들어와 있는지 · 비율이 맞는지 · 합계 용량
```

## 3. 게임에 들어가는 방식

빌드가 `04_export` 를 훑어 **data: URI 로 HTML 안에 인라인**한다(`window.BLOOM_ART`).

왜 인라인인가: 산출물이 단일 HTML 한 장이고, 아티팩트로 게시하면 외부 이미지가 CSP 로 막힌다.
휴대폰에 파일 하나만 건네도 그림이 보여야 한다.

```bash
node web/build.mjs
# web/dist/bloom.html  484KB  (아트 없음 — SVG 플레이스홀더)
# web/dist/bloom.html  6.2MB  (아트 12명 · 5.71MB)          ← 그림이 들어오면
```

**용량 예산 11MB**(`ART_BUDGET_MB`). 아티팩트 상한 16MB 에 여유를 둔 값이고, 넘으면 빌드가 경고한다.
42명 전원의 카드+썸네일을 넣을 것이므로 **카드 1장을 200KB 안쪽으로** 잡아야 한다(webp 품질 80 · 긴 변 1400px 정도).
원본 2048×2732 PNG 는 저장소·Unity 용이고, 웹 프로토타입에는 축소본을 넣는다.

화면 쪽은 `portraitSvg()` / `cardArtSvg()` 가 아트를 먼저 찾고 없으면 SVG 로 떨어진다. 둘은 같은 상자를 쓴다.

## 4. 검증

```bash
node tools/art-prompts.mjs --check   # 어휘 커버리지 · 피부톤 분포 규칙
node web/art-pack.mjs                # 들어온 파일의 비율·용량
node web/art-test.mjs                # 슬롯인 회귀 12건 (playwright 필요)
node web/app-test.mjs                # 화면 흐름 32건 — 아트가 없는 상태를 검사한다
```

`art-test.mjs` 는 검사용 단색 이미지를 42명분 잠깐 넣고 빌드해 **실제 화면에서 `<img>` 로 그려지고 디코딩까지 되는지**
보고, 끝나면 지운다. 아트 경로를 일부러 끊는 두 가지 변이(`artOf` 가 항상 null / 빌드가 인라인 생략)를 넣어
각각 4건·5건이 실패하는 것을 확인했다.

`app-test.mjs` 32건이 아트가 **하나도 없는** 상태로 도는 것이 곧 SVG 폴백 검사다.

## 5. 히어로 시험 제작 (다음 할 일)

`art-style-guide` 9절의 절차를 이 저장소 기준으로 다시 적는다.

| 단계 | 할 일 | 완료 조건 |
|---|---|---|
| 1 | 체크포인트 1개 선택, `_params.txt` 에 이름·해시 기록. 라이선스 확인(10절) | 상용 이용 가능 여부가 문서에 남는다 |
| 2 | `{quality_prefix}` 를 그 모델의 권장 품질 태그로 확정 | `_params.txt` 갱신 |
| 3 | 포즈 뱅크 5종(포지션별 1개) 확보 — 셀프 촬영 또는 3D 포즈 툴(3.4절 A·B) | `art/05_shared/pose/` 에 OpenPose JSON |
| 4 | **히어로 3명**을 끝까지 만든다. 포지션·구단·등급이 갈리게: p001(OH·SSR·t01) · p007(L·R·t01) · MB 한 명 | `04_export` 에 카드+썸네일, `art-pack` 규격 통과 |
| 5 | 휴대폰에서 확인 — 가챠 결과·로스터·라인업에서 어떻게 보이는가 | "이 그림이면 뽑고 싶은가"에 답이 나온다 |
| 6 | 태그 하나씩 빼 보며(ablation) 실제로 듣는 태그만 남겨 템플릿 확정 | 생성기의 매핑표를 고쳐 재생성 |

**3명을 먼저 하는 이유**: 1명으로는 "42명이 같은 스타일로 보이는가"(8.2절 편차 QA)를 판정할 수 없고,
42명을 만들고 나서 스타일이 갈린 것을 발견하면 전부 다시 해야 한다.

## 6. 열린 이슈

- [ ] **헤어 컬러 "선셋 오렌지" 가 스타일 가이드 2.7 의 12색 팔레트에 없다.** p025 심노을이 쓴다.
      팔레트에 오렌지를 추가하거나 데이터 값을 바꿔야 리터치 색을 정할 수 있다.
- [ ] **같은 구단 안에서 팔레트 색이 겹치는 조합 3건.** `world.md` 6.2 는 "같은 구단 안 헤어 컬러 중복 없음"이라고
      하지만, 이름이 다른 색이 12색 팔레트에서는 같은 칸으로 수렴한다.
      - 태령 피크스 #6: 진로아(애쉬 브라운) · 반소리(애쉬 그레이)
      - 연화 크레인즈 #6: 현아린(애쉬 브라운) · 우로운(차콜 그레이)
      - 라온 브리즈 #4: 공산들(골든 브라운) · 설하루(라이트 브라운)

      팔레트를 세분하거나(12 → 16색), 데이터 값을 바꾸거나, "팔레트는 같아도 명도·하이라이트로 구분한다"를
      규칙으로 명시하는 세 가지 중 하나를 정해야 한다. **42명을 만들기 전에 정할 것** — 만든 뒤에는 되돌리기 비싸다.
- [ ] **피부톤·눈매가 데이터에 없다.** 지금은 생성기가 결정적으로 배정한다. 스키마에 넣으면 캐릭터 설정과
      그림이 한 곳에서 관리된다.
- [ ] **신인 세대 카드는 아트를 가질 수 없다.** 런타임 생성이라 `pid` 가 저장소에 없다. 시즌 4 이후 스카우트 목록의
      절반 이상이 신인이므로, 장기적으로는 ① 제네릭 N 아트 몇 종을 외형 값으로 조합하거나 ② 신인도 미리 만들어 둔
      풀에서 뽑게 바꿔야 한다.
- [ ] **웹 프로토타입 인라인 용량.** 42명 × (카드+썸네일)을 예산 11MB 안에 넣으려면 카드 1장 200KB 가 상한이다.
      정식 앱(Unity)은 Addressables 원격 그룹이라 이 제약이 없다 — 웹 프로토타입만의 제약이다.
- [ ] AI 생성 고지·라이선스(art-style-guide 10절)는 여전히 미결. 체크포인트를 고르는 순간 결론이 필요하다.
